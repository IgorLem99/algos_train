# Развёртывание AlgoTrain в интернете

```
интернет ─▶ caddy (80/443, HTTPS) ─▶ app ×N ─▶ postgres
                                       └────▶ runner (изолированная сеть, без интернета)
```

| сервис | что делает |
|---|---|
| **caddy** | HTTPS (сертификат Let's Encrypt получает и продлевает сам), сжатие, балансировка между экземплярами app |
| **app** | сайт и API: регистрация, сессии, прогресс, черновики, история отправок. Без состояния — можно запускать сколько угодно копий |
| **runner** | компилирует и запускает код пользователей в песочнице. Доступен только из app, в интернет выйти не может |
| **db** | PostgreSQL 17, доступен только из app |

## 1. Сервер

Подойдёт любой VPS с Linux и Docker. Для старта хватит 4 vCPU / 8 ГБ RAM / 40 ГБ диска.
Проверка кода — самая тяжёлая часть: одна отправка занимает ядро примерно на секунду.

```bash
# Ubuntu / Debian
curl -fsSL https://get.docker.com | sh
```

DNS: A-запись (и AAAA, если есть IPv6) домена → IP сервера. Открыть порты 80 и 443 (TCP) и 443 (UDP для HTTP/3).

## 2. Настройка

```bash
git clone https://github.com/IgorLem99/algos_train.git
cd algos_train
cp .env.example .env
```

В `.env` заполнить:

```bash
DOMAIN=algotrain.example.com
POSTGRES_PASSWORD=$(openssl rand -hex 32)   # вставить сгенерированное значение
RUNNER_TOKEN=$(openssl rand -hex 32)        # вставить сгенерированное значение
ADMIN_EMAILS=you@example.com                # кто может добавлять задачи через интерфейс
```

`.env` не попадает в git и в Docker-образы.

## 3. Запуск

```bash
docker compose up -d --build
docker compose ps          # все сервисы healthy / running
docker compose logs -f app
```

Сайт откроется на `https://ДОМЕН` через несколько секунд после получения сертификата.
Зарегистрируйтесь с email из `ADMIN_EMAILS`, чтобы получить права администратора
(если список пуст, администратор — первый зарегистрированный пользователь).

Раннер при старте один раз компилирует пустое решение, чтобы прогреть кеш сборки Go, поэтому первая проверка
может занять пару лишних секунд.

## 4. Обновление

```bash
git pull
docker compose up -d --build
```

Миграции схемы БД выполняются автоматически при старте app. Если копий несколько, их сериализует advisory lock.
Сессии пользователей сохраняются: они лежат в БД.

## 5. Масштабирование

Все параметры задаются в `.env`:

| переменная | по умолчанию | смысл |
|---|---|---|
| `APP_REPLICAS` | 2 | копий app (каждая берёт до 2 CPU / 512 МБ) |
| `DB_MAX_CONNS` | 20 | соединений с БД на одну копию app (`APP_REPLICAS × DB_MAX_CONNS` < 200) |
| `RUNNER_WORKERS` | 4 | одновременных проверок кода. Разумно ставить ≈ числу ядер, выделенных раннеру |
| `RUNNER_CPUS` | 4 | ядер для раннера |
| `RUNS_PER_MINUTE` | 20 | лимит запусков на пользователя в минуту |
| `ALLOW_SIGNUP` | true | `false` закрывает регистрацию |

Если проверки стоят в очереди, увеличьте `RUNNER_WORKERS` и `RUNNER_CPUS`. Когда пользователь ждёт больше 30 секунд,
он получает ответ «сервер проверки перегружен» (503). Раннер можно вынести на отдельную машину: укажите в app
`RUNNER_URL=http://адрес:8081` и тот же `RUNNER_TOKEN`, а порт 8081 откройте только для app.

Ориентиры с локального нагрузочного теста (2 копии app, 4 воркера раннера, ноутбук):

- около 5 500 запросов/с на чтение и сохранение (p99 < 200 мс);
- около 12 проверок кода в секунду (одна проверка ≈ 0,8–1 с).

Повторить тест на своём сервере:

```bash
go run ./cmd/loadtest -url https://ДОМЕН -users 10 -workers 200 -runners 10 -d 30s
```

Флаг `-connect host:port` позволяет подключаться к конкретному адресу, например до настройки DNS.
Регистрация ограничена 20 попытками в минуту с одного IP, поэтому много аккаунтов тест сразу не создаст.
Ответы 429 на `/api/run` — это штатный лимит `RUNS_PER_MINUTE`.

На Windows с Docker Desktop тест через `localhost` может давать около 0,1 % ошибок «connection refused»:
их даёт проброс портов Docker Desktop, а не сервис. Изнутри Docker-сети ошибок нет:
`docker run --network <проект>_web … loadtest -url https://ДОМЕН -connect caddy:443 -insecure`.

## 6. Резервные копии

Все данные пользователей лежат в PostgreSQL: аккаунты, прогресс, черновики, история отправок и задачи,
добавленные через интерфейс.

```bash
# копия
docker compose exec -T db pg_dump -U algotrain -Fc algotrain > backup-$(date +%F).dump

# восстановление
docker compose exec -T db pg_restore -U algotrain -d algotrain --clean --if-exists < backup-2026-11-25.dump
```

Ежедневно через cron (храним 14 дней):

```cron
0 4 * * * cd /root/algos_train && docker compose exec -T db pg_dump -U algotrain -Fc algotrain > /var/backups/algotrain-$(date +\%F).dump && find /var/backups -name 'algotrain-*.dump' -mtime +14 -delete
```

Храните копии и вне сервера (S3, другой VPS).

## 7. Безопасность песочницы

Код пользователя выполняется так:

- в отдельном контейнере runner. У него нет сети наружу и доступа к БД, файловая система только для чтения
  (кроме tmpfs), минимальный набор capabilities, `no-new-privileges`, лимит 1024 процесса и 3 ГБ памяти;
- сборка идёт под отдельным пользователем `builder`, запуск — под уникальным uid на каждый слот (20000+N),
  без доступа к исходникам, кешу и чужим задачам;
- лимиты на процесс: CPU-время, 1,5 ГБ адресного пространства, 16 МБ на файл, 256 процессов. Ограничено
  и время: 6 с на «Запустить», 10 с на «Отправить»;
- после каждого запуска убиваются все процессы uid слота и удаляются его файлы во `/tmp`.

Для публичного сервиса с недоверенными пользователями дополнительно рекомендуется запускать раннер в
[gVisor](https://gvisor.dev): тогда даже уязвимость ядра Linux не даст выйти из контейнера.

```bash
# установить runsc по инструкции gvisor.dev, затем в /etc/docker/daemon.json:
#   { "runtimes": { "runsc": { "path": "/usr/local/bin/runsc" } } }
sudo systemctl restart docker
```

и добавить сервису `runner` в `docker-compose.yml` строку `runtime: runsc`.

## 8. Переменные окружения (справочник)

| переменная | сервис | описание |
|---|---|---|
| `MODE` | оба | `app` (по умолчанию) или `runner` |
| `ADDR` | оба | адрес HTTP-сервера |
| `DATABASE_URL` | app | `postgres://…` или `sqlite://путь` (по умолчанию `sqlite://data/algotrain.db`) |
| `RUNNER_URL`, `RUNNER_TOKEN` | app, runner | адрес раннера и общий секрет. Без `RUNNER_URL` код запускается прямо в процессе app, без песочницы (только для локальной разработки) |
| `COOKIE_SECURE` | app | `true` — cookie сессии только по HTTPS |
| `TRUST_PROXY` | app | `true` — брать IP клиента из `X-Forwarded-For` (за Caddy) |
| `ADMIN_EMAILS` | app | администраторы через запятую |
| `LOG_FORMAT`, `LOG_LEVEL` | оба | `json` / `text`; `debug` / `info` / `warn` |
| `GOCACHE_LIMIT_MB` | runner | при превышении кеш сборки очищается |
| `RUNNER_MEM_MB` | runner | лимит адресного пространства решения (по умолчанию 1536) |
