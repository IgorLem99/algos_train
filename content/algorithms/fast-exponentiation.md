## Суть за 30 секунд

Чтобы посчитать xⁿ, не нужно n−1 умножений. Заметим, что x¹³ = x⁸ · x⁴ · x¹, потому что 13 = 1101₂. Степени x, x², x⁴, x⁸… получаются последовательным **возведением в квадрат**, а в ответ мы домножаем только те, которым соответствует единичный бит показателя. Итого O(log n) умножений вместо O(n).

Это работает для **любой ассоциативной операции**: умножения по модулю, умножения матриц, композиции перестановок, сложения точек на эллиптической кривой (там это называется double-and-add).

## История

Идея очень древняя: Дональд Кнут в «Искусстве программирования» (том 2) прослеживает её до индийского трактата Пингалы о стихосложении (примерно II век до н. э.). Новую жизнь метод получил с появлением криптографии с открытым ключом: протокол Диффи–Хеллмана (1976) и RSA (Ривест, Шамир, Адлеман, 1977) требуют возводить числа в тысячи бит в степени того же размера по модулю — без быстрого возведения это было бы невозможно. Позже появились ускорения (умножение Монтгомери, 1985; оконные методы) и защищённые варианты: после работы Пола Кочера о тайминг-атаках (1996) стало ясно, что ветвление по битам секретного показателя выдаёт ключ, и в криптографии используют реализации с постоянным временем, например «лестницу Монтгомери».

## Как работает

**Итеративный вариант (справа налево по битам):**

1. `result = 1`, `base = x`.
2. Пока `n > 0`: если младший бит `n` равен 1 — `result *= base`; затем `base *= base`, `n >>= 1`.
3. Ответ — `result`.

**Инвариант:** `result · baseⁿ` всё время равно исходному xⁿ. Когда n обнуляется, `result` и есть ответ.

**Рекурсивная форма** то же самое: xⁿ = (x^(n/2))² для чётного n и x · xⁿ⁻¹ для нечётного. Глубина рекурсии — O(log n).

**По модулю.** В задачах «ответ по модулю 10⁹+7» и в криптографии берём остаток после каждого умножения: `(a·b) mod m = ((a mod m)·(b mod m)) mod m`. Числа не растут, а время остаётся O(log n).

**Матричное возведение.** Линейная рекуррентность (Фибоначчи, число путей длины k в графе, «плитки 2×n») записывается как `vₙ = M · vₙ₋₁`, значит `vₙ = Mⁿ · v₀`. Матрица k×k в степени n — это O(k³ log n): n-е число Фибоначчи для n = 10¹⁸ считается за ~60 матричных умножений 2×2.

**Обратный элемент по модулю.** По малой теореме Ферма для простого p: `a⁻¹ ≡ a^(p−2) (mod p)` — деление в задачах «по модулю» тоже сводится к быстрому возведению.

## Шаблон на Go

```go
// powMod считает base^exp mod m для любых uint64 (m > 0).
// Произведение двух 64-битных чисел не влезает в uint64, поэтому
// берём 128-битное произведение через bits.Mul64 и остаток через bits.Rem64.
func powMod(base, exp, m uint64) uint64 {
	mulMod := func(a, b uint64) uint64 {
		hi, lo := bits.Mul64(a, b)
		return bits.Rem64(hi, lo, m)
	}
	result := 1 % m
	base %= m
	for exp > 0 {
		if exp&1 == 1 { // текущий бит степени = 1 → домножаем ответ
			result = mulMod(result, base)
		}
		base = mulMod(base, base) // base^(2^k) → base^(2^(k+1))
		exp >>= 1
	}
	return result
}

// myPow — LeetCode 50: x^n для float64 и отрицательных n.
func myPow(x float64, n int) float64 {
	e := n
	if e < 0 {
		x, e = 1/x, -e // int в Go 64-битный: -(-2^31) не переполняется
	}
	res := 1.0
	for ; e > 0; e >>= 1 {
		if e&1 == 1 {
			res *= x
		}
		x *= x
	}
	return res
}
```

Матричная степень — Фибоначчи по модулю:

```go
const mod = 1_000_000_007

type Mat [2][2]int

func mul(a, b Mat) Mat {
	var c Mat
	for i := 0; i < 2; i++ {
		for j := 0; j < 2; j++ {
			for k := 0; k < 2; k++ {
				c[i][j] = (c[i][j] + a[i][k]*b[k][j]) % mod // mod² ≈ 10¹⁸ < 2⁶³
			}
		}
	}
	return c
}

// [[1,1],[1,0]]^n = [[F(n+1), F(n)], [F(n), F(n−1)]].
func fib(n int) int {
	res, m := Mat{{1, 0}, {0, 1}}, Mat{{1, 1}, {1, 0}} // res — единичная матрица
	for ; n > 0; n >>= 1 {
		if n&1 == 1 {
			res = mul(res, m)
		}
		m = mul(m, m)
	}
	return res[0][1]
}
```

Go-детали: для модулей до ~3·10⁹ хватает обычного `uint64`-умножения; для произвольного 64-битного модуля нужен `bits.Mul64` + `bits.Rem64`. Для больших чисел есть `new(big.Int).Exp(x, y, m)` — это modpow «из коробки», он же используется в `ProbablyPrime` (тест Миллера–Рабина). Но `math/big` не даёт гарантии постоянного времени, поэтому для криптографии используют пакеты `crypto/*` (сама `crypto/rsa` с Go 1.20 работает на внутренней constant-time арифметике). Переполнение `int` в Go не паникует — оно молча заворачивается, и неверный ответ легко не заметить. Не используйте `math.Pow` для целых: `float64` точно хранит только целые до 2⁵³.

## Сложность

| Вариант | Время | Память |
|---|---|---|
| Наивное xⁿ | O(n) умножений | O(1) |
| Быстрое, итеративное | O(log n) умножений | O(1) |
| Быстрое, рекурсивное | O(log n) | O(log n) стек |
| modpow с k-битными числами (школьное умножение) | O(log n · k²) | O(k) |
| Матрица d×d в степени n | O(d³ log n) | O(d²) |

## Когда применять

- «Ответ по модулю 10⁹+7», а n до 10¹⁸ — прямой цикл не уложится.
- Нужно x^n для вещественных и отрицательных n (Pow(x, n)), Super Pow (показатель задан массивом цифр).
- Линейная рекуррентность с огромным n — матричное возведение.
- Деление по простому модулю, биномиальные коэффициенты `C(n, k) mod p` — обратные через Ферма.
- Любая «применить операцию n раз», если операция ассоциативна: композиция перестановок, повторное применение функции перехода (binary lifting — та же идея для деревьев).

## Где применяется в реальном мире

### Бигтех
- **TLS и SSH**: обмен ключами Диффи–Хеллмана и подписи/шифрование RSA — это modpow с 2048–4096-битными числами; ECDHE и ECDSA используют тот же принцип для умножения точки кривой на число (double-and-add).
- **Генерация ключей**: проверка простоты кандидатов тестом Миллера–Рабина состоит из серии modpow.
- **Полиномиальное хеширование** (Rabin–Karp, поиск дубликатов, content-defined chunking в системах бэкапа и дедупликации): нужны степени основания по модулю, которые считаются быстрым возведением или предвычисляются.
- **Графовая аналитика**: число путей длины k между вершинами — элемент степени матрицы смежности Aᵏ.

### Финтех
- **Сложные проценты и дисконтирование**: `(1 + r)ⁿ` для больших n считают возведением в степень в десятичной арифметике фиксированной точности, где важны правила округления.
- **Карточные платежи EMV**: офлайн-аутентификация данных карты (SDA/DDA) основана на RSA-подписях, которые терминал проверяет modpow.
- **Кредитный риск**: при модели Маркова для рейтингов матрица переходов за n лет — это n-я степень годовой матрицы, считаемая возведением в квадрат.
- **Блокчейны**: подписи ECDSA/Schnorr на кривой secp256k1 — скалярное умножение точки, т.е. «быстрое возведение» в аддитивной записи.

### Геймдев
- **Перемотка генераторов случайных чисел**: у LCG и PCG шаг — аффинное преобразование, его n-кратное применение собирается возведением в степень за O(log n). Так раздают непересекающиеся подпоследовательности параллельным воркерам и «прыгают» к n-му числу детерминированного сида.
- **Безопасный сетевой код**: аутентификация игроков и шифрование трафика в онлайн-играх используют те же TLS/DTLS-рукопожатия с modpow и эллиптическими кривыми.
- **Процедурная генерация и вероятности**: распределение состояний марковской цепи (погода, экономика, генерация уровней) через n шагов — вектор, умноженный на Pⁿ.

## Типичные ошибки

- Переполнение при `a*b % m`, когда `m` больше ~3·10⁹: произведение не помещается в 64 бита.
- `result := 1` при `m == 1` — ответ должен быть 0; пишите `1 % m`.
- Отрицательный показатель: забыть перевернуть `x = 1/x`, или переполнить `-n` при `n = math.MinInt64`.
- Использовать `math.Pow` и приводить к `int`: потеря точности после 2⁵³.
- Рекурсия `pow(x, n/2) * pow(x, n/2)` с двумя вызовами — снова O(n); вызов должен быть один.
- Применять «теорему Ферма для обратного» к составному модулю — нужен расширенный алгоритм Евклида.
