## Суть за 30 секунд

Есть взвешенный неориентированный связный граф. **Остовное дерево** — подмножество из V−1 рёбер, которое связывает все вершины без циклов. **Минимальное остовное дерево (MST)** — такое, у которого сумма весов минимальна. Это ответ на вопрос «как дешевле всего проложить кабель, чтобы все дома оказались в одной сети».

Два классических алгоритма — оба жадные и оба корректные: **Краскал** берёт рёбра от лёгких к тяжёлым, пропуская те, что замыкают цикл; **Прим** растит одно дерево от стартовой вершины, каждый раз добавляя самое дешёвое ребро наружу.

## История

Первым задачу решил чешский математик **Отакар Борувка** в 1926 году — он проектировал экономичную электросеть для Моравии. В 1930 году **Войтех Ярник** описал алгоритм, который позже независимо переоткрыли **Роберт Прим** (1957, Bell Labs) и **Эдсгер Дейкстра** (1959), — поэтому «алгоритм Прима» иногда называют алгоритмом Ярника–Прима. **Джозеф Краскал** опубликовал свой алгоритм в 1956 году. Алгоритм Борувки до сих пор популярен в параллельных и распределённых реализациях: на каждом шаге все компоненты одновременно выбирают своё самое лёгкое исходящее ребро.

## Как работает

Оба алгоритма опираются на **свойство разреза**: разбейте вершины на две любые группы — самое лёгкое ребро между группами можно включить в MST. Доказательство обменом: если бы оптимальное дерево его не содержало, добавим это ребро — появится цикл, который пересекает разрез ещё каким-то ребром не легче нашего; выкинем его — получим дерево не тяжелее.

**Краскал:**

1. Отсортировать рёбра по весу.
2. Для каждого ребра `(u, v)`: если `u` и `v` в разных компонентах (проверка через **Union-Find / DSU**), берём ребро и объединяем компоненты; иначе пропускаем — оно замкнуло бы цикл.
3. Остановиться, набрав V−1 ребро.

**Прим:**

1. Начать с любой вершины, положить её рёбра в мин-кучу.
2. Достать самое лёгкое ребро; если оно ведёт в вершину, уже лежащую в дереве, — выбросить (ленивое удаление).
3. Иначе добавить вершину в дерево и положить в кучу её рёбра. Повторять, пока не взяты все V вершин.

В визуализации — Краскал на графе из 6 вершин: берутся B–C (1), A–C (2), D–E (2), E–F (3), ребро A–B (4) отбрасывается (A и B уже связаны через C), затем берётся B–D (5). Итого вес 13.

## Шаблон на Go

Краскал + DSU с сжатием пути и объединением по размеру:

```go
type Edge struct{ U, V, W int }

type DSU struct{ parent, size []int }

func NewDSU(n int) *DSU {
	d := &DSU{parent: make([]int, n), size: make([]int, n)}
	for i := range d.parent {
		d.parent[i], d.size[i] = i, 1
	}
	return d
}

func (d *DSU) Find(x int) int {
	for d.parent[x] != x {
		d.parent[x] = d.parent[d.parent[x]] // сжатие пути (halving)
		x = d.parent[x]
	}
	return x
}

func (d *DSU) Union(a, b int) bool {
	a, b = d.Find(a), d.Find(b)
	if a == b {
		return false // уже в одной компоненте → ребро дало бы цикл
	}
	if d.size[a] < d.size[b] {
		a, b = b, a
	}
	d.parent[b] = a
	d.size[a] += d.size[b]
	return true
}

// Kruskal возвращает вес MST и его рёбра. Если граф несвязный —
// получится минимальный остовный лес (len(tree) < n-1).
func Kruskal(n int, edges []Edge) (total int, tree []Edge) {
	edges = slices.Clone(edges) // не портим порядок у вызывающего
	slices.SortFunc(edges, func(a, b Edge) int { return a.W - b.W })
	d := NewDSU(n)
	for _, e := range edges {
		if d.Union(e.U, e.V) {
			total += e.W
			tree = append(tree, e)
			if len(tree) == n-1 {
				break
			}
		}
	}
	return total, tree
}
```

Прим с `container/heap` и ленивым удалением:

```go
type item struct{ w, v int }
type minHeap []item

func (h minHeap) Len() int           { return len(h) }
func (h minHeap) Less(i, j int) bool { return h[i].w < h[j].w }
func (h minHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *minHeap) Push(x any)        { *h = append(*h, x.(item)) }
func (h *minHeap) Pop() any {
	old := *h
	x := old[len(old)-1]
	*h = old[:len(old)-1]
	return x
}

// adj[u] — список пар {v, w}. ok == false, если граф несвязный.
func Prim(adj [][][2]int) (total int, ok bool) {
	n := len(adj)
	inTree := make([]bool, n)
	h := &minHeap{{0, 0}}
	for added := 0; h.Len() > 0; {
		it := heap.Pop(h).(item)
		if inTree[it.v] {
			continue // устаревшая запись
		}
		inTree[it.v] = true
		total += it.w
		added++
		if added == n {
			return total, true
		}
		for _, e := range adj[it.v] {
			if !inTree[e[0]] {
				heap.Push(h, item{e[1], e[0]})
			}
		}
	}
	return total, n == 0
}
```

Go-детали: компаратор `a.W - b.W` безопасен для разумных весов, но при весах около `math.MaxInt` используйте `cmp.Compare(a.W, b.W)`, чтобы разность не переполнилась. Для плотного графа, заданного матрицей (например, «соедини все точки» — LeetCode 1584), выгоднее Прим за O(V²) без кучи: массив `minDist` и линейный поиск минимума.

## Сложность

| Вариант | Время | Память |
|---|---|---|
| Краскал (сортировка + DSU) | O(E log E) | O(V + E) |
| Прим с двоичной кучей | O(E log V) | O(V + E) |
| Прим на матрице (плотный граф) | O(V²) | O(V) |
| Операция DSU (сжатие + ранги) | O(α(n)) ≈ O(1) амортизированно | O(V) |
| Борувка | O(E log V) | O(V + E) |

Правило выбора: разреженный граф или рёбра уже списком — Краскал; плотный граф или матрица расстояний — Прим.

## Когда применять

- «Соединить все точки/города/серверы с минимальной стоимостью», «минимальная стоимость прокладки сети».
- Граф **неориентированный**, нужна связность, а не путь между двумя точками (для пути — Дейкстра).
- **Кластеризация**: построить MST и удалить k−1 самых тяжёлых рёбер — получится k кластеров (single-linkage).
- Вариации: максимальное остовное дерево (сортируем по убыванию), «минимакс-путь» (путь в MST минимизирует максимальное ребро), критические и псевдокритические рёбра (LeetCode 1489), задачи «построй колодец или проведи трубу» с виртуальной вершиной (LeetCode 1168).

## Где применяется в реальном мире

### Бигтех
- **Проектирование сетей** (оптоволокно, электросети, трубопроводы): MST даёт нижнюю оценку стоимости и стартовую топологию, к которой потом добавляют резервные линии.
- **Кластеризация**: single-linkage иерархическая кластеризация эквивалентна построению MST; на этой связи основаны, например, алгоритмы семейства HDBSCAN.
- **Сегментация изображений**: алгоритм Фельценшвальба–Хуттенлохера (2004) обрабатывает рёбра между пикселями в порядке веса, как Краскал, и сливает области через Union-Find.
- **Приближённое решение задачи коммивояжёра**: обход MST даёт 2-приближение для метрического TSP, а алгоритм Кристофидеса строится поверх MST — используется в логистике и планировании маршрутов.

### Финтех
- **Сети корреляций активов**: по матрице корреляций строят граф с расстоянием `d = √(2(1 − ρ))` и берут MST — классическая работа Мантеньи (1999) показала, что такое дерево выявляет секторную структуру рынка.
- **Иерархическая кластеризация портфеля**: методы вроде Hierarchical Risk Parity используют single-linkage кластеризацию (то есть по сути MST) активов перед распределением весов.
- **Поиск связанных аккаунтов** в антифроде: устройства, карты и адреса — вершины, сила связи — вес; остовный лес и Union-Find быстро собирают «кольца» связанных учётных записей.

### Геймдев
- **Генерация лабиринтов**: рандомизированный Краскал (случайные веса стен + Union-Find) и рандомизированный Прим дают «идеальные» лабиринты без циклов, где между любыми двумя клетками ровно один путь.
- **Процедурные подземелья**: распространённый приём — соединить комнаты триангуляцией Делоне, взять MST как гарантию связности и вернуть часть отброшенных рёбер, чтобы появились петли.
- **Дороги и сети в стратегиях и симуляторах**: автоматическая прокладка самой дешёвой сети дорог, труб или линий электропередачи между постройками.

## Типичные ошибки

- Применять MST к **ориентированному** графу: там нужна другая задача — минимальное ориентированное дерево (алгоритм Чу–Лю/Эдмондса).
- Путать MST с деревом кратчайших путей: MST минимизирует **сумму всех рёбер**, а не расстояние от корня до каждой вершины.
- Не проверить связность: если набралось меньше V−1 ребра, остовного дерева не существует.
- DSU без сжатия пути и рангов — на цепочках `Find` деградирует до O(n).
- В Приме не пропускать устаревшие записи из кучи — вершина добавится дважды, вес будет завышен.
- Сортировать по весу оригинальный слайс рёбер, который ещё нужен в исходном порядке (например, для ответа по индексам рёбер).
