## Суть за 30 секунд

Монотонный стек — обычный стек, в котором значения всегда упорядочены (например, убывают от дна к вершине). Перед `push` мы снимаем все элементы, которые нарушили бы порядок, и **в момент снятия** узнаём для них ответ: «вот он, первый больший элемент справа».

Интуиция — очередь на парад: невысокий человек, за которым встал более высокий, больше никому сзади не загораживает обзор, его можно забыть. В стеке остаются только «кандидаты», которые ещё могут быть кому-то ответом. Каждый элемент кладётся и снимается не более одного раза, поэтому вместо O(n²) получаем O(n).

**Монотонный дек** — то же самое, но элементы ещё и уходят с другого конца, когда выпадают из скользящего окна. Голова дека — максимум (или минимум) окна.

## История

Конкретного автора у приёма нет — это фольклор алгоритмических соревнований, но опирается он на хорошо известные работы:

- **1972** — алгоритм Грэхема для выпуклой оболочки: точки идут по углу, и стек хранит только «левые повороты» — по сути монотонный стек в геометрии. В **1979** А. М. Эндрю предложил вариант monotone chain с сортировкой по координате.
- Задача «All Nearest Smaller Values» (для каждого элемента — ближайший меньший слева) изучалась в параллельных алгоритмах; известна работа Беркмана, Шибера и Вишкина (1993). Последовательное решение — ровно монотонный стек.
- **2006** — Даниэль Лемир опубликовал алгоритм потокового max/min-фильтра, использующий не более трёх сравнений на элемент, — монотонные деки для максимума и минимума окна.

## Как работает

**Next Greater Element** (Daily Temperatures из визуализации):

1. Стек хранит **индексы** дней, которые ещё ждут более тёплого дня; температуры по этим индексам убывают от дна к вершине.
2. Приходит день `i`. Пока температура на вершине меньше `t[i]` — снимаем вершину `j`: для неё ответ `i − j`.
3. Кладём `i`. Стек снова убывающий.
4. Индексы, оставшиеся в стеке в конце, тёплого дня не дождались — ответ 0.

Почему храним индексы, а не значения: по индексу можно получить и значение, и расстояние, и позицию для ответа.

**Какой порядок держать** — зависит от вопроса:

| ищем | стек по значениям (от дна к вершине) | снимаем, пока |
| --- | --- | --- |
| следующий больший | убывает | вершина < текущего |
| следующий меньший | возрастает | вершина > текущего |
| предыдущий больший/меньший | так же, но ответ — вершина *после* снятий | — |

**Largest Rectangle in Histogram**: стек возрастающих высот. Когда приходит столбец ниже вершины, вершина «закончилась»: справа её ограничивает текущий столбец, слева — новый элемент под ней в стеке. Ширина = `i − left − 1`. Фиктивный столбец высоты 0 в конце выталкивает всё.

**Sliding Window Maximum** (монотонный дек): дек хранит индексы с убывающими значениями. Новый элемент выталкивает с хвоста всех, кто меньше (они уже никогда не станут максимумом — новый элемент больше и проживёт в окне дольше). С головы уходит индекс, выпавший из окна. Максимум окна — голова.

## Шаблон на Go

```go
// nextGreater — индекс ближайшего справа большего элемента, -1 если нет.
func nextGreater(a []int) []int {
	res := make([]int, len(a))
	for i := range res {
		res[i] = -1
	}
	st := make([]int, 0, len(a)) // индексы; a[st[...]] строго убывает
	for i, x := range a {
		for len(st) > 0 && a[st[len(st)-1]] < x {
			res[st[len(st)-1]] = i
			st = st[:len(st)-1]
		}
		st = append(st, i)
	}
	return res
}

// largestRectangleArea — максимальный прямоугольник в гистограмме.
func largestRectangleArea(h []int) int {
	st := make([]int, 0, len(h)+1) // индексы; высоты возрастают
	best := 0
	for i := 0; i <= len(h); i++ {
		cur := 0 // фиктивный столбец высоты 0 в конце
		if i < len(h) {
			cur = h[i]
		}
		for len(st) > 0 && h[st[len(st)-1]] >= cur {
			height := h[st[len(st)-1]]
			st = st[:len(st)-1]
			left := -1
			if len(st) > 0 {
				left = st[len(st)-1]
			}
			best = max(best, height*(i-left-1))
		}
		st = append(st, i)
	}
	return best
}
```

```go
// maxSlidingWindow — максимум каждого окна длины k через монотонный дек.
func maxSlidingWindow(a []int, k int) []int {
	if k <= 0 || k > len(a) {
		return nil
	}
	dq := make([]int, 0, k) // индексы; a[dq[...]] убывает, голова — максимум
	res := make([]int, 0, len(a)-k+1)
	for i, x := range a {
		if len(dq) > 0 && dq[0] <= i-k {
			dq = dq[1:] // голова выпала из окна
		}
		for len(dq) > 0 && a[dq[len(dq)-1]] <= x {
			dq = dq[:len(dq)-1] // хвост больше никогда не станет максимумом
		}
		dq = append(dq, i)
		if i >= k-1 {
			res = append(res, a[dq[0]])
		}
	}
	return res
}
```

Заметки по Go: дек на срезе с `dq = dq[1:]` прост и амортизированно O(1) — `append` время от времени перевыделит массив и «забудет» отрезанное начало. Для долгоживущего потока (миллионы тиков) лучше кольцевой буфер фиксированной ёмкости. `container/list` тоже годится как дек (`PushBack`, `Remove(Front())`), но каждый элемент — отдельная аллокация и `any`-значение, это медленнее среза в разы.

## Сложность

| операция | время | память |
| --- | --- | --- |
| next greater / smaller для всех элементов | O(n) — каждый индекс 1 push и ≤ 1 pop | O(n) |
| largest rectangle in histogram | O(n) | O(n) |
| максимум/минимум всех окон длины k | O(n) | O(k) |
| одна операция push | O(1) амортизированно (иногда много pop) | — |
| наивное решение | O(n²) или O(n·k) | O(1) |

## Когда применять

- «Для каждого элемента найди **ближайший** больший/меньший слева или справа» — Daily Temperatures, Next Greater Element, Stock Span.
- «Сколько дней до…», «на сколько элементов видно…», «сколько подряд не больше…».
- Прямоугольники и площади по высотам: Largest Rectangle, Maximal Rectangle (по строкам матрицы), Trapping Rain Water (стековый вариант).
- «Максимум/минимум в каждом окне» — монотонный дек.
- «Удали k цифр, чтобы число стало минимальным», «наименьшая подпоследовательность с уникальными символами» — жадность + монотонный стек.
- Сумма минимумов всех подмассивов — для каждого элемента «зона, где он минимум», через предыдущий и следующий меньший.

## Где применяется в реальном мире

### Бигтех
- **Linux TCP**: скользящий минимум RTT и (в BBR) скользящий максимум пропускной способности хранятся через `lib/win_minmax.c` (алгоритм Кэтлин Николс). Это близкая идея: вместо всего окна держится несколько «кандидатов», вытесняемых более сильными значениями.
- **Обработка сигналов и изображений**: морфологические фильтры erosion/dilation — это min/max по скользящему окну; эффективные реализации (алгоритм Лемира, ван Херка — Гиля — Вермана) работают за O(1) на элемент независимо от размера окна.
- **Стриминговые агрегаты**: max/min за последние N событий в системах мониторинга и потоковой обработки — стандартная техника на монотонном деке (или «очередь на двух стеках»).
- **Строковые индексы**: обработка LCP-массива при работе с суффиксными массивами (поиск повторяющихся подстрок) делается стековым проходом в духе largest rectangle.

### Финтех
- **Индикаторы high/low за N баров** (каналы Дончиана, стохастик): rolling max/min через монотонный дек — O(1) амортизированно на новый тик, вместо пересмотра всего окна.
- **Stock Span**: сколько дней подряд цена была не выше сегодняшней — каноническая задача монотонного стека, используемая в техническом анализе.
- **Пробои уровней и просадки**: «когда цена впервые превысит текущий уровень» — next greater element по ряду цен; на исторических данных — за один проход.

### Геймдев
- **Выпуклые оболочки** для 2D-коллайдеров и упрощения силуэтов: Graham scan и monotone chain Эндрю держат стек точек с инвариантом «только левые повороты».
- **Профилирование кадров**: максимальное время кадра за последние N кадров в HUD — монотонный дек ловит фризы (hitches) без пересчёта окна.
- **Netcode**: размер jitter-буфера и оценки пинга часто опираются на максимум/минимум RTT за последние N секунд — скользящий max/min, который удобно держать монотонным деком.

## Типичные ошибки

- **Строгое или нестрогое сравнение** (`<` или `<=`): при равных значениях меняется ответ (ближайший *больший* или *не меньший*); в задачах «сумма минимумов подмассивов» нужно `<` с одной стороны и `<=` с другой, иначе подмассивы посчитаются дважды.
- **Хранение значений вместо индексов** — потом не вычислить расстояние и не проверить выпадение из окна.
- **Забыть «добить» стек в конце**: элементы, оставшиеся в стеке, тоже требуют ответа (часто −1 или 0) — или добавьте фиктивный элемент-ограничитель.
- **Дек: проверка выпадения из окна** — `dq[0] <= i−k`, а не `< i−k`.
- **Неправильная ширина в гистограмме**: левая граница — новый элемент под вершиной после pop, а не сам снятый индекс.
- **Думать, что вложенный `for` делает O(n²)** — каждая операция pop «оплачена» предыдущим push, суммарно не больше n.
