## Суть за 30 секунд

Алгоритм Дейкстры находит кратчайшие расстояния от одной вершины до всех остальных во взвешенном графе, где **веса неотрицательны**. Это BFS, у которого вместо обычной очереди — **очередь с приоритетом**: всегда раскрываем вершину с наименьшим известным расстоянием.

Аналогия — пожар, разгорающийся из точки по сети бикфордовых шнуров разной длины: огонь доходит до каждого узла самым быстрым путём, и момент, когда он туда дошёл, и есть кратчайшее расстояние. Ключевая идея: вершина, извлечённая из кучи с минимальным `dist`, уже **окончательна** — любой обходной путь пойдёт через вершины, до которых не ближе, а отрицательных рёбер, способных «срезать», нет.

## История

Эдсгер Дейкстра придумал алгоритм в 1956 году, а опубликовал в 1959-м в журнале Numerische Mathematik в короткой заметке «A note on two problems in connexion with graphs» (вторая задача там — минимальное остовное дерево). Задача была демонстрационной: показать возможности нового компьютера ARMAC, найдя кратчайший маршрут между городами Нидерландов на упрощённой карте.

В интервью 2001 года Дейкстра вспоминал, что придумал алгоритм минут за двадцать, сидя с невестой на террасе амстердамского кафе, без карандаша и бумаги, — и считал, что именно отсутствие бумаги заставило его избегать лишней сложности.

Исходная версия работала за O(V²). С двоичной кучей получается O((V + E) log V), а в 1984 году Фредман и Тарьян с фибоначчиевой кучей довели теоретическую оценку до O(E + V log V). В 1968 году Питер Харт, Нильс Нильссон и Бертрам Рафаэль из Стэнфордского исследовательского института (SRI) предложили **`A*`** — Дейкстру с эвристикой, направляющей поиск к цели; он появился в проекте мобильного робота Shakey.

## Как работает

1. `dist[src] = 0`, остальные — ∞. Кладём `(0, src)` в min-кучу.
2. Достаём из кучи пару `(d, u)` с минимальным `d`. Если `d > dist[u]` — запись устарела (до u уже нашли путь короче), пропускаем.
3. Иначе u **зафиксирована**. Для каждого ребра u → v с весом w делаем **релаксацию**: если `dist[u] + w < dist[v]`, обновляем `dist[v]`, запоминаем `prev[v] = u` и кладём `(dist[v], v)` в кучу.
4. Повторяем, пока куча не пуста (или пока не извлекли целевую вершину, если нужен путь только до неё).

В визуализации граф неориентированный, старт — A. Под вершинами текущие `dist`, справа — содержимое кучи. Обратите внимание на запись вида «(…) устарел — пропускаем»: Go-шный `container/heap` (как и большинство библиотечных куч) не умеет уменьшать ключ, поэтому мы просто кладём новую пару, а старую игнорируем при извлечении. Это называется **ленивое удаление**. Зелёные рёбра в конце — **дерево кратчайших путей**, которое восстанавливается по `prev`.

**Почему не работает с отрицательными весами.** Вершина фиксируется в момент извлечения. Если позже найдётся ребро с отрицательным весом, ведущее в неё, путь мог бы стать короче — но мы её уже «закрыли». Для отрицательных весов нужен Беллман–Форд, а для поиска отрицательного цикла — тем более.

### A* — Дейкстра с компасом

Дейкстра расходится от старта во все стороны одинаково. Если нужна одна конкретная цель и есть оценка расстояния до неё, можно расставить приоритеты умнее: `f(v) = g(v) + h(v)`, где `g` — найденное расстояние от старта (как `dist` у Дейкстры), а `h` — **эвристика**, оценка оставшегося пути до цели.

- Если `h` **допустима** (никогда не переоценивает реальный остаток), A* находит оптимальный путь. Если она ещё и **согласована** (`h(u) ≤ w(u,v) + h(v)`), каждую вершину достаточно раскрыть один раз — как у Дейкстры.
- `h = 0` — это ровно Дейкстра. Чем точнее `h`, тем меньше вершин раскрывается.
- На сетке с 4 направлениями — манхэттенское расстояние, с 8 направлениями — октильное (или Чебышёва при диагонали той же цены), в свободном пространстве — евклидово.
- **Weighted `A*`** (`g + ε·h`, ε > 1) жертвует оптимальностью ради скорости — частый компромисс в играх.

## Шаблон на Go

```go
type Edge struct{ To, W int }

type entry struct{ node, dist int }
type minHeap []entry

func (h minHeap) Len() int           { return len(h) }
func (h minHeap) Less(i, j int) bool { return h[i].dist < h[j].dist }
func (h minHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *minHeap) Push(x any)        { *h = append(*h, x.(entry)) }
func (h *minHeap) Pop() any {
	old := *h
	x := old[len(old)-1]
	*h = old[:len(old)-1]
	return x
}

// dijkstra возвращает расстояния (math.MaxInt — недостижима) и массив предков.
// Веса обязаны быть неотрицательными.
func dijkstra(adj [][]Edge, src int) (dist, prev []int) {
	n := len(adj)
	dist = make([]int, n)
	prev = make([]int, n)
	for i := range dist {
		dist[i] = math.MaxInt
		prev[i] = -1
	}
	dist[src] = 0
	h := &minHeap{{src, 0}}
	for h.Len() > 0 {
		cur := heap.Pop(h).(entry)
		if cur.dist > dist[cur.node] {
			continue // устаревшая запись (lazy deletion)
		}
		for _, e := range adj[cur.node] {
			if nd := cur.dist + e.W; nd < dist[e.To] {
				dist[e.To] = nd
				prev[e.To] = cur.node
				heap.Push(h, entry{e.To, nd})
			}
		}
	}
	return dist, prev
}

// path восстанавливает маршрут src → dst по массиву prev.
func path(prev []int, dst int) []int {
	var p []int
	for v := dst; v != -1; v = prev[v] {
		p = append(p, v)
	}
	slices.Reverse(p)
	return p
}
```

Детали Go:

- `container/heap` не поддерживает decrease-key «из коробки». Есть два пути: ленивое удаление (как выше — проще, куча растёт до O(E)) или индексированная куча с полем `index` и `heap.Fix` (куча не больше V, но кода больше).
- Переполнение: `math.MaxInt + w` переполнится в отрицательное число. В шаблоне это невозможно — мы релаксируем только из извлечённых вершин, у которых `dist` конечен. Но если пишете проверку вида `dist[u] + w < dist[v]` для произвольного u — сначала проверьте, что `dist[u] != math.MaxInt`.
- Для плотных графов (E ≈ V²) простая версия за O(V²) без кучи — выбирать минимум линейным проходом по массиву — быстрее варианта с кучей.

## Сложность

| Вариант | Время | Память |
|---|---|---|
| Двоичная куча (ленивое удаление) | O((V + E) log V) | O(V + E) |
| Массив без кучи (для плотных графов) | O(V²) | O(V) |
| Фибоначчиева куча (теоретически) | O(E + V log V) | O(V + E) |
| A* | от O(путь) до как у Дейкстры — зависит от эвристики | O(раскрытых вершин) |
| Для сравнения: BFS (все веса равны) | O(V + E) | O(V) |

## Когда применять

- **«Кратчайший / самый дешёвый / самый быстрый путь»** при неотрицательных весах: Network Delay Time, Path With Minimum Effort, Swim in Rising Water.
- Сетка, где клетки или переходы **стоят по-разному** (иначе хватит BFS).
- **Минимакс-пути:** «минимизировать максимальное ребро на пути» — та же Дейкстра, где вместо суммы берётся `max(dist[u], w)`.
- **Максимальная вероятность пути** — Дейкстра с max-кучей и произведением (или с весами `−log p`).
- **Состояние шире вершины:** (город, оставшееся топливо), (клетка, число использованных скидок) — Дейкстра по расширенному графу состояний.

Когда **не** Дейкстра: отрицательные веса → Беллман–Форд; ограничение на число рёбер (Cheapest Flights Within K Stops) → Беллман–Форд на K раундов или BFS по состоянию (вершина, число пересадок); веса 0/1 → 0-1 BFS; все пары вершин на маленьком графе → Флойд–Уоршелл.

## Где применяется в реальном мире

### Бигтех
- **Маршрутизация в интернете:** протоколы link-state OSPF и IS-IS. Каждый маршрутизатор знает топологию своей области и запускает Дейкстру (SPF), строя дерево кратчайших путей от себя; по нему заполняется таблица маршрутизации. Спецификация OSPF прямо ссылается на алгоритм Дейкстры.
- **Навигация и карты:** открытые маршрутизаторы OSRM, GraphHopper и Valhalla используют потомков Дейкстры с предобработкой — Contraction Hierarchies, многоуровневую Дейкстру, двунаправленный A*. Чистая Дейкстра на графе дорог целого континента слишком медленна для ответа за миллисекунды.
- **Traffic engineering:** в MPLS-TE путь туннеля ищется через CSPF — Дейкстру на графе, из которого предварительно убраны каналы без нужной свободной полосы.

### Финтех
- **Lightning Network:** узел lnd ищет маршрут платежа модифицированной Дейкстрой по графу платёжных каналов. Вес ребра учитывает комиссию, блокировку средств по времени и вероятность успеха; поиск идёт от получателя к отправителю, потому что комиссия каждого прыжка зависит от суммы, которую нужно передать дальше.
- **Маршрутизация трансграничных платежей:** выбор цепочки банков-корреспондентов или платёжных провайдеров с минимальной суммарной комиссией или временем — кратчайший путь во взвешенном графе (общая практика платёжных оркестраторов).
- **Контрпример — арбитраж валют:** обмен — это произведение курсов; переходя к весам `−log(курс)`, получаем сумму, но веса становятся **отрицательными**. Здесь Дейкстра неприменима: прибыльный арбитраж — это отрицательный цикл, и ищут его Беллманом–Фордом.

### Геймдев
- **Поиск пути `A*` на сетке и navmesh:** стандарт индустрии. Библиотека Recast & Detour строит навигационную сетку и ищет путь A* по её полигонам; на Recast основана навигация в Unreal Engine, Godot использует Recast для построения navmesh.
- **Dijkstra maps в рогаликах:** Дейкстра от нескольких целей сразу (игрок, сокровища) даёт поле расстояний; монстры просто спускаются «под горку», а умножение поля на отрицательный коэффициент даёт поведение бегства. Приём популяризирован статьёй автора Brogue «The Incredible Power of Dijkstra Maps».
- **Тактика и стратегии:** зона хода юнита при разной стоимости местности (лес — 2 очка движения, дорога — 1) — Дейкстра, остановленная по бюджету; карты угроз для ИИ строятся так же.

## Типичные ошибки

- Запускать на графе с отрицательными весами — ответ будет неверным без какой-либо ошибки.
- Фиксировать вершину (помечать visited) при **добавлении** в кучу, как в BFS. Фиксировать можно только при **извлечении**.
- Не пропускать устаревшие записи: результат будет верным, но на плотных графах время сильно растёт.
- Использовать обычную очередь вместо кучи — получится не Дейкстра, а некорректный (или экспоненциально медленный) BFS.
- Для неориентированного графа добавить ребро только в одну сторону.
- Останавливаться, когда цель **добавлена** в кучу, а не когда она **извлечена** — путь может быть ещё не кратчайшим.
- В A* взять эвристику, которая переоценивает (например, евклидово расстояние, умноженное на большую стоимость клетки), и удивляться неоптимальным путям.
