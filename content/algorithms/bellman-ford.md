## Суть за 30 секунд

Беллман–Форд ищет кратчайшие расстояния от одной вершины до всех остальных, **даже если у рёбер бывают отрицательные веса**. Вместо хитрой очереди, как у Дейкстры, он действует «в лоб»: V−1 раз подряд пытается улучшить (релаксировать) расстояние по каждому ребру. Это медленнее — O(V·E), — зато алгоритм умеет то, чего не умеет Дейкстра: **замечать отрицательные циклы**.

Аналогия: слух о «самом дешёвом маршруте» расходится по сети. За один раунд каждый узел сообщает соседям, сколько стоит добраться до него. За k раундов правильная информация проходит по любому пути из k рёбер, а длиннее V−1 ребра простой путь быть не может.

## История

Идею независимо опубликовали несколько исследователей середины 1950-х: Альфонсо Шимбел (1955), Лестер Форд-младший (1956) и Ричард Беллман (1958, статья «On a routing problem»); в 1959 году вариант с очередью описал Эдвард Мур, поэтому иногда пишут «Беллман–Форд–Мур». Имя закрепилось за Беллманом и Фордом.

Алгоритм очень естественно распределяется: каждый узел хранит только свои оценки расстояний и обменивается ими с соседями. Поэтому именно «распределённый Беллман–Форд» лёг в основу **distance-vector** маршрутизации: на нём работала ранняя маршрутизация ARPANET (в конце 1970-х её заменили на link-state протокол с Дейкстрой) и протокол RIP.

## Как работает

Пусть `dist[s] = 0`, остальные `∞`. **Релаксация** ребра `u → v` с весом `w`: если `dist[u] + w < dist[v]`, то `dist[v] = dist[u] + w`.

1. Повторяем V−1 раз: проходим по **всем** рёбрам и релаксируем каждое.
2. Если за раунд ничего не изменилось — ответ готов, можно выйти раньше.
3. Делаем ещё один, V-й проход. Если какое-то ребро всё ещё улучшается — в графе есть **отрицательный цикл**, достижимый из `s`: по нему можно ходить бесконечно, уменьшая стоимость, и «кратчайшего пути» не существует.

**Инвариант:** после k раундов `dist[v]` не больше длины кратчайшего пути до `v`, использующего не более k рёбер. В графе без отрицательных циклов кратчайший путь простой, то есть в нём не больше V−1 ребра — отсюда число раундов.

Почему Дейкстра не справляется: она «замораживает» вершину, как только достаёт её из кучи, полагая, что дальше путь может только дорожать. Отрицательное ребро ломает это предположение: `S→A (2)`, `S→B (5)`, `B→A (−4)` — Дейкстра зафиксирует A = 2, хотя на самом деле A = 1.

В визуализации всё сходится уже за первый раунд, потому что рёбра удачно упорядочены; при неудачном порядке понадобятся все V−1 раундов.

**Арбитраж валют.** Пусть ребро `i → j` — обмен по курсу `r(i,j)`. Цикл выгоден, если произведение курсов больше 1. Логарифм превращает произведение в сумму, а минус — «больше» в «меньше»: взяв вес `w = −log r`, получаем «произведение > 1 ⇔ сумма весов < 0». Выгодный цикл обмена — это ровно отрицательный цикл.

## Шаблон на Go

```go
type Edge struct{ From, To, W int }

const inf = math.MaxInt64 / 4 // запас, чтобы inf + w не переполнился

// BellmanFord возвращает кратчайшие расстояния от src и признак
// отрицательного цикла, достижимого из src.
func BellmanFord(n int, edges []Edge, src int) (dist []int, negCycle bool) {
	dist = make([]int, n)
	for i := range dist {
		dist[i] = inf
	}
	dist[src] = 0
	for round := 0; round < n-1; round++ {
		changed := false
		for _, e := range edges {
			if dist[e.From] != inf && dist[e.From]+e.W < dist[e.To] {
				dist[e.To] = dist[e.From] + e.W
				changed = true
			}
		}
		if !changed {
			return dist, false // ранний выход: всё уже сошлось
		}
	}
	// V-й проход: если что-то ещё улучшается — есть отрицательный цикл
	for _, e := range edges {
		if dist[e.From] != inf && dist[e.From]+e.W < dist[e.To] {
			return dist, true
		}
	}
	return dist, false
}
```

Детектор арбитража. Все `dist` стартуют с 0 — это эквивалентно виртуальному истоку, соединённому со всеми вершинами рёбрами веса 0, поэтому цикл найдётся в любой части графа:

```go
// rates[i][j] — сколько единиц валюты j дают за 1 единицу i (0 — пары нет).
func HasArbitrage(rates [][]float64) bool {
	n := len(rates)
	const eps = 1e-12 // float64 копит погрешность: без допуска будут ложные срабатывания
	dist := make([]float64, n)
	for round := 0; round < n; round++ {
		changed := false
		for i := 0; i < n; i++ {
			for j := 0; j < n; j++ {
				if rates[i][j] <= 0 {
					continue
				}
				w := -math.Log(rates[i][j])
				if dist[i]+w < dist[j]-eps {
					dist[j] = dist[i] + w
					changed = true
				}
			}
		}
		if !changed {
			return false
		}
	}
	return true // улучшения не прекратились за n раундов
}
```

Go-детали: `int` 64-битный и при переполнении молча «заворачивается», поэтому `math.MaxInt64 + w` превратится в огромное отрицательное число — отсюда `inf = MaxInt64/4` и проверка `dist[e.From] != inf`. Для восстановления пути храните `prev[v]`; чтобы вытащить сам отрицательный цикл, от вершины, улучшившейся на V-м проходе, сделайте V шагов по `prev` — окажетесь гарантированно внутри цикла.

## Сложность

| Вариант | Время | Память |
|---|---|---|
| Классический Беллман–Форд | O(V·E) | O(V) |
| С ранним выходом (лучший случай) | O(E) | O(V) |
| SPFA (очередь изменившихся вершин) | в среднем быстрее, худший O(V·E) | O(V) |
| Не более k рёбер в пути | O(k·E) | O(V) |
| Дейкстра для сравнения (только w ≥ 0) | O((V+E) log V) | O(V) |

## Когда применять

- В условии есть **отрицательные веса**: скидки, кэшбэк, возвраты, «бонусные» переходы.
- Нужно **обнаружить** выгодный цикл: арбитраж, бесконечный фарм ресурсов, противоречивые ограничения.
- Ограничение на **число рёбер** в пути: «не более k пересадок» (LeetCode 787 Cheapest Flights Within K Stops) — делаем k+1 раундов, релаксируя по **копии** массива с прошлого раунда.
- **Системы разностных ограничений** вида `x_j − x_i ≤ c`: ребро `i → j` веса `c`, решение — расстояния от виртуального истока, отрицательный цикл — система несовместна.
- Алгоритм Джонсона (все пары кратчайших путей в разреженном графе с отрицательными весами): Беллман–Форд считает потенциалы, после которых веса неотрицательны, и дальше V раз запускается Дейкстра.

## Где применяется в реальном мире

### Бигтех
- **RIP** (Routing Information Protocol) — классический distance-vector протокол: роутер периодически рассылает соседям таблицу «до какой сети сколько хопов», а соседи релаксируют свои маршруты. Это и есть распределённый Беллман–Форд; бесконечность в RIP равна 16 хопам.
- **Проблема «счёта до бесконечности»**: при обрыве линии узлы в distance-vector сети начинают по кругу поднимать друг другу метрику. Против неё придуманы split horizon, poison reverse и ограничение метрики — классическая тема собеседований по сетям.
- **BGP**, протокол маршрутизации между автономными системами интернета, — path-vector: развитие той же идеи, где вместе с маршрутом передаётся весь путь AS_PATH (чтобы отсекать петли), а выбор делается по политикам, а не только по сумме весов.
- Протоколы для mesh-сетей вроде **Babel** и корпоративный EIGRP также относятся к семейству distance-vector и решают его классические проблемы с петлями.

### Финтех
- **Поиск арбитража**: валюты — вершины, курсы с учётом комиссий — рёбра с весом `−log(rate)`. Отрицательный цикл = цепочка обменов, возвращающая больше, чем вложено. Это классический учебный пример (есть в CLRS), и та же модель используется ботами, ищущими треугольный арбитраж между криптовалютными парами и пулами.
- **Проверка согласованности собственных котировок**: если в кросс-курсах, которые публикует ваш прайсинг, есть отрицательный цикл, контрагенты смогут «прокачать» деньги через вас.
- **Самый дешёвый перевод не более чем через k посредников** (банки-корреспонденты, платёжные шлюзы с комиссиями) — ровно ограниченный по рёбрам Беллман–Форд.

### Геймдев
- **Проверка игровой экономики**: ресурсы — вершины, обмены у NPC и рецепты крафта — рёбра с `−log(коэффициента)`. Отрицательный цикл — эксплойт с бесконечной генерацией золота; его можно искать автоматически при балансировке.
- **Поиск пути с бонусами**: если клетки могут давать «отрицательную стоимость» (лечение, ускорение), A* и Дейкстра становятся некорректны; на небольших графах выручает Беллман–Форд.
- **Ограничения на таймлайне** катсцен и анимаций («B не раньше чем через 2 с после A», «C не позже D») — система разностных ограничений; отрицательный цикл означает противоречивый сценарий.

## Типичные ошибки

- Переполнение: `inf + w` при `inf = math.MaxInt64` даёт отрицательное число. Берите запас и не релаксируйте из вершин с `dist == inf`.
- В задаче «не более k рёбер» обновлять `dist` прямо в текущем раунде: тогда за один раунд путь удлиняется на несколько рёбер. Нужна копия массива прошлого раунда.
- Делать V−1 проход и забыть V-й — отрицательный цикл останется незамеченным, а ответ будет мусором.
- Искать цикл из одного истока, когда цикл может быть в недостижимой части графа: для «есть ли цикл где угодно» стартуйте со всеми `dist = 0`.
- Сравнивать `float64` без эпсилона при `−log` курсов: ошибки округления дают фантомный «арбитраж».
- Применять к **неориентированному** графу с отрицательным ребром: такое ребро само по себе — отрицательный цикл из двух шагов.
