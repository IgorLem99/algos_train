## Суть за 30 секунд

DFS идёт из вершины в первого непосещённого соседа, оттуда — снова в непосещённого соседа, и так до тупика; в тупике **откатывается** к последней вершине, у которой остались неисследованные рёбра. Путь от старта до текущей вершины хранится в стеке — явном или в стеке рекурсии.

Аналогия — исследование пещеры с мелом: помечаем каждый пройденный зал и всегда сворачиваем в ещё не помеченный проход, а когда идти некуда — возвращаемся по своим следам. DFS не даёт кратчайших путей (это работа BFS), зато отлично отвечает на вопросы о **структуре** графа: что с чем связано, есть ли цикл, в каком порядке выполнять зависимости, какие рёбра критичны.

## История

Прототип DFS — метод Тремо для прохождения лабиринтов (Франция, XIX век): помечать пройденные коридоры и не входить второй раз в уже исследованные. Его описание встречается, например, у Эдуарда Люка (1882).

Как инструмент алгоритмики DFS раскрыли Роберт Тарьян и Джон Хопкрофт в начале 1970-х. Статья Тарьяна «Depth-first search and linear graph algorithms» (1972) показала, что с помощью DFS за линейное время находятся компоненты сильной связности и двусвязные компоненты; вместе с Хопкрофтом он построил на DFS линейный тест планарности. В 1986 году оба получили премию Тьюринга за фундаментальные достижения в разработке и анализе алгоритмов и структур данных.

Задача об эйлеровом пути восходит к Леонарду Эйлеру и семи мостам Кёнигсберга (1736). Эффективный алгоритм построения эйлерова цикла носит имя Карла Хирхольцера — его работа была опубликована в 1873 году, уже после смерти автора.

## Как работает

**Базовый DFS:** помечаем вершину посещённой, затем рекурсивно запускаемся из каждого непосещённого соседа. Каждая вершина входит в рекурсию один раз, каждое ребро просматривается один (ориентированный граф) или два (неориентированный) раза → O(V + E).

**Компоненты связности:** перебираем все вершины; встретили непосещённую — это новая компонента, запускаем из неё DFS, который «заливает» всю компоненту. В визуализации так считаются острова на сетке: каждая новая непосещённая клетка суши даёт новый остров, а DFS на явном стеке помечает все его клетки.

### Поиск цикла: три цвета

В **неориентированном** графе цикл есть, если DFS встретил посещённого соседа, который не является родителем текущей вершины. В **ориентированном** так нельзя: посещённая вершина могла быть обработана в другой, уже законченной ветке (cross-edge), и цикла через неё нет. Поэтому используют три цвета:

- **белый** — вершина ещё не посещена;
- **серый** — вершина в текущем пути: мы вошли в неё, но ещё не вышли (она на стеке рекурсии);
- **чёрный** — вершина и всё, что из неё достижимо, полностью обработаны.

Ребро в **серую** вершину — **обратное ребро**: мы вернулись в вершину текущего пути, значит, нашли цикл. Ребро в чёрную вершину безопасно.

Тот же DFS даёт и **топологическую сортировку**: вершина становится чёрной только после всех своих потомков, поэтому развёрнутый порядок «почернения» (post-order) — топологический порядок. На идее «времени входа» и «минимального достижимого времени входа» (low-link) построены алгоритмы Тарьяна для компонент сильной связности, мостов и точек сочленения.

### Эйлеров путь: алгоритм Хирхольцера

Эйлеров путь проходит по **каждому ребру ровно один раз** (вершины можно повторять). Он существует, если граф связен (по рёбрам) и:

- в неориентированном графе нечётную степень имеют 0 вершин (тогда есть эйлеров цикл) или ровно 2 (путь идёт от одной к другой);
- в ориентированном — у всех вершин входящая степень равна исходящей, кроме, возможно, старта (исходящих на 1 больше) и финиша (входящих на 1 больше).

Алгоритм Хирхольцера — это DFS по **рёбрам**: из текущей вершины идём по любому неиспользованному ребру и сразу удаляем его. Когда из вершины больше некуда идти, дописываем её в ответ (post-order). В конце ответ разворачиваем. Если жадный проход упёрся в тупик раньше времени, оставшиеся рёбра образуют циклы, которые рекурсия «вклеит» в путь при откате — именно поэтому вершину пишут в ответ при выходе, а не при входе.

В задаче **Reconstruct Itinerary** билеты — рёбра, и нужен лексикографически наименьший маршрут: сортируем списки соседей и всегда идём в наименьшего. Простой жадный проход без post-order ломается, если наименьший сосед ведёт в тупик.

## Шаблон на Go

```go
// Подсчёт компонент связности на сетке (Number of Islands).
func numIslands(grid [][]byte) int {
	R, C := len(grid), len(grid[0])
	var dfs func(r, c int)
	dfs = func(r, c int) {
		if r < 0 || c < 0 || r >= R || c >= C || grid[r][c] != '1' {
			return
		}
		grid[r][c] = '0' // помечаем посещённой прямо в сетке
		dfs(r+1, c)
		dfs(r-1, c)
		dfs(r, c+1)
		dfs(r, c-1)
	}
	count := 0
	for r := range grid {
		for c := range grid[r] {
			if grid[r][c] == '1' {
				count++
				dfs(r, c)
			}
		}
	}
	return count
}

// Поиск цикла в ориентированном графе тремя цветами.
const (
	white = iota // не посещена
	gray         // на текущем пути (на стеке рекурсии)
	black        // полностью обработана
)

func hasCycle(adj [][]int) bool {
	color := make([]int, len(adj))
	var dfs func(u int) bool
	dfs = func(u int) bool {
		color[u] = gray
		for _, v := range adj[u] {
			if color[v] == gray {
				return true // обратное ребро → цикл
			}
			if color[v] == white && dfs(v) {
				return true
			}
		}
		color[u] = black
		return false
	}
	for u := range adj {
		if color[u] == white && dfs(u) {
			return true
		}
	}
	return false
}
```

```go
// Эйлеров путь (Хирхольцер) для Reconstruct Itinerary.
func findItinerary(tickets [][]string) []string {
	adj := map[string][]string{}
	for _, t := range tickets {
		adj[t[0]] = append(adj[t[0]], t[1])
	}
	for k := range adj {
		slices.Sort(adj[k])
		slices.Reverse(adj[k]) // берём с конца — так первым идёт наименьший
	}
	var route []string
	var dfs func(u string)
	dfs = func(u string) {
		for len(adj[u]) > 0 {
			last := len(adj[u]) - 1
			v := adj[u][last]
			adj[u] = adj[u][:last] // ребро использовано
			dfs(v)
		}
		route = append(route, u) // post-order: из u больше некуда идти
	}
	dfs("JFK")
	slices.Reverse(route)
	return route
}
```

Детали Go:

- Рекурсия в Go не упирается в маленький лимит: стек горутины растёт динамически (по умолчанию до 1 ГБ на 64-битных системах). Но сетка 1000×1000 сплошной суши — это миллион вложенных вызовов и сотни мегабайт стека. Для таких входов используйте явный стек `[][2]int`, как в визуализации.
- Удаление ребра «с конца среза» (`adj[u] = adj[u][:last]`) — O(1); удаление из начала через `adj[u][1:]` тоже O(1), но сортировку пришлось бы делать по возрастанию.
- Сборщик мусора Go — **трёхцветный** concurrent mark-sweep: объекты бывают белыми, серыми и чёрными в том же смысле, что и вершины в DFS (серые — найдены, но их ссылки ещё не просмотрены).

## Сложность

| Задача | Время | Память |
|---|---|---|
| DFS / компоненты связности | O(V + E) | O(V) — visited и стек |
| DFS по сетке R×C | O(R·C) | O(R·C) в худшем случае на стек |
| Поиск цикла (3 цвета) | O(V + E) | O(V) |
| Мосты, точки сочленения, SCC (Тарьян) | O(V + E) | O(V) |
| Эйлеров путь (Хирхольцер) | O(E), с сортировкой соседей O(E log E) | O(V + E) |

## Когда применять

- **«Сколько компонент / островов / провинций», «можно ли добраться из A в B»**, «размер наибольшей области».
- **«Есть ли цикл», «можно ли пройти все курсы», «найти deadlock»** — три цвета (или алгоритм Кана).
- **Заливка от границы:** Surrounded Regions, Pacific Atlantic Water Flow — DFS запускается от краёв сетки, а не от каждой клетки.
- **Все пути** из A в B в DAG (All Paths From Source to Target) — DFS с возвратом.
- **«Пройти каждое ребро ровно один раз»**, «восстановить маршрут по билетам», «последовательность де Брёйна» — эйлеров путь.
- **«Критические соединения»**, «точки отказа» — мосты и точки сочленения (low-link).
- DFS + мемоизация по вершине — DP на DAG: Longest Increasing Path in a Matrix.

Вариации: итеративный DFS на стеке, клонирование графа (DFS + map старый→новый), DFS с передачей родителя для неориентированных графов, алгоритмы Тарьяна и Косарайю для SCC.

## Где применяется в реальном мире

### Бигтех
- **Компилятор Go:** escape analysis и другие межпроцедурные проходы обрабатывают функции группами снизу вверх по графу вызовов; группы — компоненты сильной связности, найденные алгоритмом Тарьяна (`ir.VisitFuncsBottomUp`). А циклы в графе импортов команда `go` отвергает с ошибкой «import cycle not allowed».
- **Сборка мусора:** фаза разметки обходит граф объектов от корней (стеки, глобальные переменные) и помечает всё достижимое; Go использует трёхцветную разметку, где серые объекты — фронт обхода.
- **PostgreSQL:** если транзакция ждёт блокировку дольше `deadlock_timeout`, запускается поиск цикла в графе ожиданий (wait-for graph) — рекурсивный обход от ожидающего процесса; найденный цикл означает deadlock, и одна из транзакций прерывается.
- **Пакетные менеджеры и сборка:** обнаружение циклических зависимостей и топологический порядок установки/сборки — DFS по графу зависимостей.

### Финтех
- **Карусельные схемы и round-tripping:** деньги, прошедшие по цепочке счетов и вернувшиеся к отправителю, — это цикл в ориентированном графе переводов. Поиск таких циклов ограниченной длины (DFS с ограничением глубины по окну времени) — общая практика антифрод- и AML-систем.
- **Deadlock-детекторы в транзакционных СУБД:** PostgreSQL и InnoDB (MySQL) ищут циклы в графе ожиданий блокировок, чтобы откатить одну из взаимно заблокированных транзакций — критично для систем с конкурентными списаниями с одних и тех же счетов.
- **Группы связанных заёмщиков:** регуляторы требуют оценивать концентрацию кредитного риска по группам связанных лиц; группа — компонента связности графа владения и контроля, которую находят обходом графа.

### Геймдев
- **Генерация лабиринтов:** «recursive backtracker» — это рандомизированный DFS: идём к случайному непосещённому соседу, ломая стену, а в тупике откатываемся.
- **Заливка регионов:** открытие пустой области в «Сапёре», выделение одноцветной области в match-3, подсчёт «дыханий» группы камней в игре го — всё это flood fill, т.е. DFS (или BFS) по клеткам.
- **Проверка процедурных карт:** после генерации подземелья обход из точки входа проверяет, что все комнаты достижимы, а недостижимые «островки» удаляются или соединяются коридорами.
- **Головоломки «одним росчерком»:** нарисовать фигуру, не отрывая карандаша и не проходя линию дважды, — эйлеров путь; генератор такого уровня проверяет условия на степени вершин.

## Типичные ошибки

- В ориентированном графе искать цикл с булевым `visited` — cross-edge в уже обработанную ветку даёт ложный цикл. Нужны три цвета.
- В неориентированном графе не передать родителя — каждое ребро (u, v) выглядит как цикл u → v → u.
- Помечать вершину посещённой после рекурсивных вызовов, а не до — бесконечная рекурсия на любом цикле.
- Забыть запустить DFS из **всех** вершин: граф может быть несвязным, и часть циклов/компонент останется незамеченной.
- Reconstruct Itinerary: жадно идти в наименьшего соседа и писать вершину в ответ **при входе** — на тупиковой ветке маршрут оборвётся. Писать нужно при выходе и разворачивать.
- Портить входную сетку пометками, когда она нужна дальше (или по условию её нельзя менять) — используйте отдельный `visited`.
