## Суть за 30 секунд

Вместо перебора всех пар `(i, j)` держим два индекса и двигаем их по правилу, которое гарантирует: отброшенные варианты точно не являются ответом. Каждый индекс проходит массив не больше одного раза — получаем O(n) времени и O(1) памяти.

Интуиция: в отсортированном массиве ищем пару с суммой `t`. Если `a[L] + a[R]` слишком мало, то `a[L]` не подойдёт ни с каким элементом — даже с самым большим `a[R]`. Значит, `L` можно выбросить навсегда. Симметрично для `R`. Это не трюк, а доказательство, «зашитое» в цикл.

## История

У приёма нет единственного автора — это фольклор, который проявляется во множестве классических алгоритмов:

- **1945** — Джон фон Нейман описал сортировку слиянием; её шаг merge — два указателя по двум отсортированным массивам.
- **1959–1961** — Тони Хоар придумал quicksort; его схема разбиения (partition) — два указателя, идущие навстречу друг другу от краёв.
- **1976** — Эдсгер Дейкстра в книге «A Discipline of Programming» разобрал задачу о голландском флаге — разбиение на три группы тремя указателями.

Название «two pointers» закрепилось уже в культуре олимпиадного программирования и подготовки к собеседованиям.

## Как работает

Есть два основных режима.

**1. Встречные указатели** (`L` в начале, `R` в конце, движутся навстречу). Нужна монотонность — обычно отсортированный массив.

1. `L = 0`, `R = n − 1`.
2. Пока `L < R`: считаем `s = a[L] + a[R]`.
3. `s == t` — ответ. `s < t` — нужно больше, `L++`. `s > t` — нужно меньше, `R−−`.

Ключевой инвариант: если ответ существует, он лежит внутри `[L..R]`. В визуализации ищем сумму 14 в `[1, 3, 4, 6, 8, 11, 15]`: `1 + 15 = 16` — слишком много, `R−−`; `1 + 11 = 12` — мало, `L++`; `3 + 11 = 14` — нашли.

<div data-viz="two-pointers"></div>

**2. Попутные указатели** (оба идут слева направо с разной скоростью). Быстрый `r` читает, медленный `w` пишет. Так фильтруют массив на месте: удалить дубликаты, удалить заданное значение, сдвинуть нули в конец. Инвариант: `a[:w]` — уже готовый ответ.

Родственники: быстрый/медленный указатель в связном списке (середина, цикл Флойда), два указателя по двум массивам (merge, пересечение), скользящее окно (оба указателя идут вправо, а между ними — «окно» с инвариантом).

## Шаблон на Go

```go
// pairWithSum — встречные указатели по отсортированному срезу.
func pairWithSum(a []int, target int) (int, int, bool) {
	l, r := 0, len(a)-1
	for l < r {
		switch s := a[l] + a[r]; {
		case s == target:
			return l, r, true
		case s < target:
			l++
		default:
			r--
		}
	}
	return -1, -1, false
}

// dedupSorted — попутные указатели: r читает, w пишет. Аналог slices.Compact.
func dedupSorted(a []int) []int {
	if len(a) == 0 {
		return a
	}
	w := 1
	for r := 1; r < len(a); r++ {
		if a[r] != a[w-1] {
			a[w] = a[r]
			w++
		}
	}
	return a[:w]
}
```

```go
// threeSum — сортировка + встречные указатели + пропуск дубликатов.
func threeSum(nums []int) [][]int {
	slices.Sort(nums)
	var res [][]int
	for i := 0; i < len(nums)-2; i++ {
		if i > 0 && nums[i] == nums[i-1] {
			continue // тот же первый элемент уже разобран
		}
		l, r := i+1, len(nums)-1
		for l < r {
			s := nums[i] + nums[l] + nums[r]
			switch {
			case s < 0:
				l++
			case s > 0:
				r--
			default:
				res = append(res, []int{nums[i], nums[l], nums[r]})
				for l < r && nums[l] == nums[l+1] {
					l++
				}
				for l < r && nums[r] == nums[r-1] {
					r--
				}
				l++
				r--
			}
		}
	}
	return res
}
```

В стандартной библиотеке Go приём встречается постоянно: `slices.Compact` и `slices.DeleteFunc` (Go 1.21) — это read/write-указатели, `slices.Reverse` — встречные указатели с обменом. Обмен в Go пишется без временной переменной: `a[l], a[r] = a[r], a[l]`. Помните, что `dedupSorted` и `slices.Compact` меняют исходный срез — у вызывающего кода останется «мусор» за пределами новой длины.

## Сложность

| операция | время | память |
| --- | --- | --- |
| пара с суммой в отсортированном массиве | O(n) | O(1) |
| то же, если массив сначала надо отсортировать | O(n log n) | O(log n) на сортировку |
| 3Sum | O(n²) | O(1) кроме ответа |
| удаление элементов на месте (read/write) | O(n) | O(1) |
| слияние двух отсортированных массивов | O(n + m) | O(n + m) для результата |

## Когда применять

- Массив **отсортирован** (или его можно отсортировать без потери ответа) и нужна пара/тройка с условием на сумму или разность.
- «Палиндром?», «развернуть на месте» — встречные указатели с краёв.
- «Удалить/сдвинуть элементы **на месте**, O(1) памяти» — попутные read/write.
- «Container With Most Water», «Trapping Rain Water» — двигаем указатель с меньшей высотой, потому что он ограничивает ответ.
- Два отсортированных массива: слияние, пересечение, «ближайшая пара».
- Если просят O(1) памяти там, где напрашивается хеш-таблица, — проверьте, нельзя ли отсортировать и пройти двумя указателями.

Вариации: 3Sum/4Sum (фиксируем элементы внешним циклом), Dutch national flag (три указателя), быстрый/медленный указатель в списках.

## Где применяется в реальном мире

### Бигтех
- **PostgreSQL Merge Join**: оба входа отсортированы по ключу соединения; два курсора идут вперёд, и всегда сдвигается тот, у кого ключ меньше.
- **Поисковые движки** (Lucene/Elasticsearch): AND-запрос — пересечение posting lists, отсортированных по docID; продвигается отстающий список (с ускорением через skip-списки).
- **LSM-деревья** (LevelDB, RocksDB): compaction сливает отсортированные SST-файлы — обобщение merge двух указателей на k входов через кучу. Так же устроена внешняя сортировка.
- **Unix `comm` и `join`**: сравнивают два отсортированных файла построчно одним проходом.

### Финтех
- **Сверка выписок**: поток банка и внутренний леджер, оба отсортированы по ID или времени, проходятся merge-ом; элементы без пары — расхождения для разбора.
- **As-of join** (`aj` в kdb+/q, `merge_asof` в pandas): к каждой сделке присоединяется последняя котировка не позже её времени — один проход двумя указателями по двум рядам, отсортированным по времени.
- **Матчинг заявок**: пока лучшая цена покупки ≥ лучшей цены продажи, сделки идут с вершин двух сторон стакана — концептуально два указателя, сходящиеся от лучших цен.

### Геймдев
- **Sweep and prune** (sort and sweep) в broad-phase физики: границы AABB проецируются на ось, сортируются, и проход по ним находит перекрывающиеся интервалы. Вариант реализован, например, в Bullet (`btAxisSweep3`).
- **Компактизация массивов сущностей и частиц**: read/write-указатели удаляют «мёртвые» элементы за один проход без аллокаций, сохраняя плотность данных для кеша.
- **Слияние отсортированных списков** — например, списков команд отрисовки, собранных разными потоками и отсортированных по ключу, — в один упорядоченный поток.

## Типичные ошибки

- **`l <= r` вместо `l < r`** — один элемент используется дважды как пара сам с собой.
- **Массив не отсортирован** — встречные указатели дают неверный ответ без всяких ошибок. Если нужны исходные индексы (Two Sum), сортировка их теряет — сортируйте пары `(значение, индекс)` или используйте map.
- **Дубликаты в 3Sum**: забыть пропуск одинаковых `nums[i]` или одинаковых `l`/`r` после найденной тройки.
- **Переполнение суммы** `a[l] + a[r]` для `int32`.
- **Бесконечный цикл**: ни одна из ветвей не сдвигает указатель (например, после найденного ответа забыли `l++`/`r--`).
- **Пересечение срезов**: `a[:w]` разделяет память с исходным срезом — изменения видны обоим.
