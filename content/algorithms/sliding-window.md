## Суть за 30 секунд

Задачи вида «лучший подотрезок/подстрока с условием» наивно решаются перебором всех `O(n²)` отрезков. Скользящее окно держит один текущий отрезок `[L..R]` и его сводку (сумму, счётчики символов). `R` расширяет окно, `L` сжимает его, когда условие нарушено. Каждый элемент один раз входит в окно и один раз выходит — O(n).

Аналогия — рамка, которую двигают по ленте: при сдвиге не нужно пересматривать всё, что внутри, достаточно учесть элемент, который вошёл справа, и элемент, который вышел слева.

## История

Как приём решения задач скользящее окно — фольклор без конкретного автора. Сама идея «окна, которое сдвигается по потоку» хорошо задокументирована в сетях и обработке данных:

- **1974–1981** — в работе Винтона Серфа и Роберта Кана (1974) и затем в спецификации TCP (RFC 793, 1981) окно определяет, сколько неподтверждённых данных отправитель может держать «в полёте»; подтверждения сдвигают его вперёд.
- **1987** — алгоритм Рабина–Карпа использует *rolling hash*: хеш окна строки пересчитывается за O(1) при сдвиге на символ.
- **1996** — Эндрю Триджелл в rsync применил скользящую (rolling) контрольную сумму, чтобы находить совпадающие блоки файла в любом смещении.

## Как работает

Есть два вида окна.

**Фиксированное окно длины k**: считаем сводку первых k элементов, затем на каждом шаге добавляем `a[i]` и вычитаем `a[i−k]`. Так считают скользящее среднее, максимум суммы k подряд, анаграммы длины k в строке.

**Переменное окно** — основной шаблон:

1. `L = 0`. Для каждого `R` от 0 до n−1 добавляем `a[R]` в сводку окна.
2. Пока окно **нарушает** условие — убираем `a[L]` из сводки и делаем `L++`.
3. Окно снова валидно — обновляем ответ (для задач «максимальная длина»).

Для задач «минимальная длина» порядок зеркальный: пока окно **валидно** — обновляем ответ и сжимаем.

Почему это корректно: если окно `[L..R]` невалидно, то любое более широкое окно `[L'..R]` с `L' < L` тоже невалидно (условие *монотонно* по вложенности). Поэтому `L` никогда не нужно двигать назад.

В визуализации — самая длинная подстрока без повторов в «abcabcbb». Инвариант: в окне все символы уникальны. Когда приходит повтор, `L` прыгает сразу за предыдущее вхождение этого символа — это оптимизация через map «символ → последний индекс».

## Шаблон на Go

```go
// Переменное окно, «максимальная длина»:
// самая длинная подстрока без повторяющихся символов.
func lengthOfLongestSubstring(s string) int {
	last := make(map[byte]int) // символ → последний индекс
	best, l := 0, 0
	for r := 0; r < len(s); r++ {
		if i, ok := last[s[r]]; ok && i >= l {
			l = i + 1 // повтор внутри окна — сразу прыгаем за него
		}
		last[s[r]] = r
		best = max(best, r-l+1)
	}
	return best
}

// Переменное окно, «минимальная длина»: кратчайший подмассив
// с суммой >= target. Работает только для неотрицательных чисел.
func minSubArrayLen(target int, nums []int) int {
	best := math.MaxInt
	sum, l := 0, 0
	for r, x := range nums {
		sum += x
		for sum >= target { // окно валидно — фиксируем и сжимаем
			best = min(best, r-l+1)
			sum -= nums[l]
			l++
		}
	}
	if best == math.MaxInt {
		return 0
	}
	return best
}
```

```go
// Фиксированное окно длины k (0 < k <= len(a)): максимальная сумма k подряд.
func maxSumWindow(a []int, k int) int {
	sum := 0
	for i := 0; i < k; i++ {
		sum += a[i]
	}
	best := sum
	for i := k; i < len(a); i++ {
		sum += a[i] - a[i-k] // вошёл a[i], вышел a[i-k]
		best = max(best, sum)
	}
	return best
}

// Окно со счётчиками: найти все начала анаграмм p в s.
func findAnagrams(s, p string) []int {
	if len(p) > len(s) {
		return nil
	}
	var need, have [26]int
	for i := 0; i < len(p); i++ {
		need[p[i]-'a']++
		have[s[i]-'a']++
	}
	var res []int
	if have == need { // массивы в Go сравниваются целиком
		res = append(res, 0)
	}
	for i := len(p); i < len(s); i++ {
		have[s[i]-'a']++
		have[s[i-len(p)]-'a']--
		if have == need {
			res = append(res, i-len(p)+1)
		}
	}
	return res
}
```

Заметки по Go: встроенные `min`/`max` появились в Go 1.21. Для строк из ASCII индексируйте байты `s[r]`, для Unicode переведите строку в `[]rune` — иначе окно будет резать многобайтовые символы. Счётчики по алфавиту выгоднее держать в массиве `[26]int`, а не в map: массивы сравнимы оператором `==` и не аллоцируют.

## Сложность

| операция | время | память |
| --- | --- | --- |
| фиксированное окно | O(n) | O(1) |
| переменное окно (каждый элемент входит и выходит 1 раз) | O(n) | O(k) — размер сводки |
| окно со счётчиками алфавита Σ | O(n) или O(n·Σ) при сравнении массивов | O(Σ) |
| наивный перебор всех подотрезков | O(n²) – O(n³) | O(1) |

## Когда применять

- «Самый длинный / самый короткий **подмассив или подстрока** такой, что…»
- «Подстрока, содержащая все символы t» (Minimum Window Substring), «не более k различных символов», «замени не более k символов».
- «Максимальная/средняя сумма k подряд», «все анаграммы» — фиксированное окно.
- Условие **монотонно**: если окно невалидно, расширение его не исправит (или наоборот). Именно это позволяет не двигать `L` назад.
- Есть отрицательные числа и условие на сумму? Окно ломается — переходите к префиксным суммам + map.
- Нужен максимум/минимум окна — окно + монотонный дек.

## Где применяется в реальном мире

### Бигтех
- **TCP**: скользящее окно управления потоком — отправитель держит в полёте не больше объявленного получателем окна; каждый ACK сдвигает левую границу вперёд.
- **Rate limiting**: Cloudflare описывала алгоритм *sliding window counter* — оценка запросов за последнюю минуту как взвешенная сумма текущего и предыдущего окна; *sliding log* на sorted set в Redis — распространённая практика.
- **rsync**: rolling checksum Триджелла пересчитывается за O(1) при сдвиге на байт, что позволяет найти совпадающие блоки в любом смещении и передать только разницу.
- **Стриминг** (Apache Flink, Kafka Streams): sliding/hopping windows по времени для агрегатов — количество событий, суммы, перцентили за последние N минут.

### Финтех
- **Скользящие индикаторы**: SMA, rolling VWAP, rolling-волатильность — сумма обновляется добавлением нового тика и вычитанием выпавшего, без пересчёта всего окна.
- **Velocity-правила антифрода**: «не больше N операций или суммы X по карте за последние 10 минут» — окно по времени над потоком транзакций.
- **Лимиты частоты заявок**: биржи и брокерские шлюзы ограничивают число сообщений в секунду на сессию; контроль — скользящее окно по времени.

### Геймдев
- **Счётчик FPS / frame time**: среднее за последние N кадров — кольцевой буфер и бегущая сумма вместо пересчёта.
- **Netcode поверх UDP**: получатель подтверждает последние 32 пакета битовой маской относительно последнего номера — схема, подробно описанная Гленном Фидлером (Gaffer On Games). Это окно по номерам пакетов.
- **Распознавание комбо в файтингах**: буфер ввода хранит нажатия за последние N кадров; приём засчитывается, если вся последовательность уложилась в окно.
- **Серверная валидация движения**: перемещение игрока за окно времени не должно превышать допустимое — простая проверка против speed hack.

## Типичные ошибки

- **Сжатие через `if` вместо `for`**: за один шаг `R` может понадобиться выкинуть несколько элементов слева.
- **Окно для отрицательных чисел**: при сумме с отрицательными элементами сжатие не монотонно — ответ будет неверным.
- **Устаревший индекс в map**: в задаче без повторов нужна проверка `i >= l` — символ мог встретиться *до* текущего окна.
- **Длина окна** — `r − l + 1`, а не `r − l`.
- **Неправильный момент обновления ответа**: для «максимума» — после сжатия, для «минимума» — внутри цикла сжатия.
- **Пустой результат**: забыть вернуть 0, если окно ни разу не стало валидным (`best` остался `math.MaxInt`).
