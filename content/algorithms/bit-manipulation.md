## Суть за 30 секунд

Число в памяти — это просто 64 флажка. Битовые операции (`&`, `|`, `^`, `<<`, `>>`) обрабатывают все 64 флажка **одной инструкцией процессора**. Поэтому `uint64` можно использовать как множество из 64 элементов, а массив `[]uint64` — как компактное множество из миллионов элементов с операциями пересечения и объединения «по 64 за раз».

Пара свойств, на которых держится половина задач: **`x ^ x = 0`** (одинаковое взаимно уничтожается) и **`n & (n−1)`** гасит младшую единицу.

## История

Двоичную логику формализовал Джордж Буль в середине XIX века, а Клод Шеннон в магистерской диссертации 1937 года показал, что булева алгебра описывает релейные схемы, — так логические операции стали «железом». Трюк `n & (n−1)` для подсчёта единиц обычно приписывают Питеру Вегнеру (1960); он же встречается как упражнение в книге Кернигана и Ритчи. Знаменитые сборники приёмов — меморандум MIT HAKMEM (1972) и книга Генри Уоррена «Hacker's Delight» (2002). В современных x86 и ARM есть отдельные инструкции для подсчёта единиц и ведущих/хвостовых нулей — Go вызывает их через пакет `math/bits`.

## Как работает

**Базовые операции на Go:**

- `x & y` — AND, пересечение множеств; `x & 1` — проверка на нечётность.
- `x | y` — OR, объединение; `x | 1<<k` — установить бит k.
- `x ^ y` — XOR, симметрическая разность; `x ^ 1<<k` — переключить бит k.
- `x &^ y` — AND NOT (оператор есть только в Go): `x &^ (1<<k)` сбрасывает бит k.
- `^x` — побитовое NOT (в Go нет `~`).
- `x >> k & 1` — значение бита k; `x << k` — умножение на 2ᵏ.
- `x & -x` — младший установленный бит; `n > 0 && n&(n-1) == 0` — степень двойки.

**XOR и «единственное число».** XOR коммутативен и ассоциативен, `a ^ a = 0`, `a ^ 0 = a`. Если XOR-нуть весь массив, где каждое число встречается дважды, кроме одного, пары исчезнут, и останется ответ. Ни map, ни сортировки — O(n) времени, O(1) памяти.

**`n & (n−1)` и подсчёт единиц.** Вычитание единицы превращает младшую единицу в 0, а все нули правее неё — в единицы. AND с исходным числом обнуляет эту «хвостовую» часть целиком: младшая единица исчезает, остальные биты не меняются. Значит, цикл `for n != 0 { n &= n - 1 }` делает ровно столько итераций, сколько в числе единиц.

**Маски как подмножества.** Число `mask` от 0 до 2ⁿ−1 кодирует подмножество n элементов: бит i = «элемент i взят». Это даёт перебор всех подмножеств без рекурсии и DP по подмножествам (`dp[mask]`, задача коммивояжёра для n ≤ 20).

## Шаблон на Go

```go
func singleNumber(nums []int) int { // все, кроме одного, встречаются дважды
	x := 0
	for _, v := range nums {
		x ^= v
	}
	return x
}

func popcountKernighan(n uint64) int { // столько итераций, сколько единиц
	c := 0
	for n != 0 {
		n &= n - 1 // гасим младшую единицу
		c++
	}
	return c
}

func isPowerOfTwo(n int) bool { return n > 0 && n&(n-1) == 0 }
func lowestBit(n int) int     { return n & -n } // 0b10100 → 0b00100

// В продакшене — math/bits: компилятор превращает это в POPCNT/TZCNT/LZCNT.
func bitTricks(x uint64) (ones, trailingZeros, length int) {
	return bits.OnesCount64(x), bits.TrailingZeros64(x), bits.Len64(x)
}

// Перебор всех подмножеств: mask — подмножество items.
func subsets(items []string) [][]string {
	n := len(items)
	res := make([][]string, 0, 1<<n)
	for mask := 0; mask < 1<<n; mask++ {
		var cur []string
		for i := 0; i < n; i++ {
			if mask>>i&1 == 1 {
				cur = append(cur, items[i])
			}
		}
		res = append(res, cur)
	}
	return res
}
```

Битсет — множество целых `[0, n)` по одному биту на элемент:

```go
type Bitset []uint64

func NewBitset(n int) Bitset    { return make(Bitset, (n+63)/64) }
func (b Bitset) Set(i int)      { b[i>>6] |= 1 << (uint(i) & 63) }
func (b Bitset) Clear(i int)    { b[i>>6] &^= 1 << (uint(i) & 63) }
func (b Bitset) Has(i int) bool { return b[i>>6]&(1<<(uint(i)&63)) != 0 }
func (b Bitset) And(o Bitset) { // пересечение — 64 элемента за операцию
	for k := range b {
		b[k] &= o[k]
	}
}
func (b Bitset) Count() int {
	c := 0
	for _, w := range b {
		c += bits.OnesCount64(w)
	}
	return c
}
```

Go-детали: `>>` для знаковых типов — арифметический сдвиг (размножает знаковый бит), для беззнаковых — логический; для битовых задач предпочитайте `uint64`. Сдвиг на величину ≥ разрядности определён (0, а для отрицательного числа при сдвиге вправо — −1), в отличие от неопределённого поведения в C. Приоритет операторов в Go отличается от C: `&`, `<<`, `>>` имеют приоритет умножения, а `|` и `^` — сложения, поэтому `x>>i&1 == 1` читается как `((x>>i)&1) == 1`. Переполнение `int` молча «заворачивается» по модулю 2⁶⁴.

## Сложность

| Операция | Время | Память |
|---|---|---|
| AND / OR / XOR / сдвиг | O(1) | O(1) |
| Popcount: `bits.OnesCount64` | O(1), одна инструкция | O(1) |
| Popcount: цикл `n & (n−1)` | O(число единиц) | O(1) |
| Single Number через XOR | O(n) | O(1) |
| Перебор всех подмножеств | O(2ⁿ · n) | O(n) на подмножество |
| Пересечение битсетов на N элементов | O(N / 64) | O(N / 64) |

## Когда применять

- «Каждый элемент встречается дважды/трижды, кроме одного» — XOR или подсчёт битов по позициям.
- «Без дополнительной памяти», «без сложения и умножения» (Sum of Two Integers).
- n ≤ 20 и нужно перебирать подмножества — маски, DP по маскам.
- Нужно хранить множество флагов или большое множество маленьких целых компактно — битсет.
- Вариации: Counting Bits (`dp[i] = dp[i>>1] + i&1`), Reverse Bits, Missing Number (XOR индексов и значений), Single Number III (разделить по младшему различающемуся биту), Gray code (`i ^ i>>1`), Hamming distance (`popcount(a ^ b)`).

## Где применяется в реальном мире

### Бигтех
- **Roaring bitmaps** — сжатые битсеты, на которых построены инвертированные индексы и фильтры в Apache Lucene, Druid, Spark, ClickHouse и других системах: пересечение условий запроса — это AND битовых карт.
- **Фильтры Блума**: k хешей устанавливают биты в битовом массиве; LSM-хранилища (Cassandra, RocksDB, HBase) хранят такой фильтр для каждого файла и не читают диск, если ключа точно нет.
- **HyperLogLog** (например, `PFCOUNT` в Redis) оценивает число уникальных элементов по длине серии нулей в начале (или конце) хешей — это `bits.LeadingZeros64` / `bits.TrailingZeros64`.
- **Флаги и права доступа**: биты `rwx` в Unix, `os.O_CREATE|os.O_WRONLY` в Go, битовые поля в заголовках сетевых протоколов.

### Финтех
- **Бинарные протоколы рыночных данных**: в форматах вроде CME MDP 3.0 (на основе SBE) флаги сообщения упакованы в битовые поля — разбор идёт масками и сдвигами без аллокаций.
- **Фильтры Блума в Bitcoin**: BIP 37 позволял лёгким кошелькам запрашивать у узлов только «свои» транзакции через Bloom-фильтр (позже его сменили компактные фильтры BIP 157/158).
- **Правила и сегменты в антифроде и скоринге**: принадлежность клиента к множеству сегментов или срабатывание набора правил удобно хранить битсетом и проверять пересечения одной операцией.

### Геймдев
- **Битборды в шахматных движках**: позиция — двенадцать 64-битных масок, по одной на тип фигуры; генерация ходов — сдвиги и AND, а для дальнобойных фигур Stockfish и другие движки используют «магические битборды».
- **Слои столкновений**: в Unity маска слоёв — 32-битное число (`LayerMask` в `Physics.Raycast`), в Box2D у фикстур есть `categoryBits` и `maskBits`; столкновение проверяется одним AND.
- **Bitmask-автотайлинг**: соседи клетки кодируются 4 или 8 битами, получившееся число — индекс нужного тайла с правильными краями.
- **ECS**: набор компонентов сущности часто представлен битовой маской, и выборка «все сущности с Position и Velocity» — проверка `mask & required == required`.

## Типичные ошибки

- Забыть скобки и неверно оценить приоритет операторов при переносе формулы из C/C++ или Java.
- Использовать знаковый `int` и получить арифметический сдвиг с размножением знака вместо логического.
- Писать `1 << k` для k ≥ 63 в `int` — получите знаковый бит или 0; используйте `uint64(1) << k`.
- Путать `^x` (NOT в Go) с XOR и искать оператор `~`.
- Самописный цикл подсчёта битов вместо `bits.OnesCount64` в горячем коде.
- Перебирать маски для n > 25: 2ⁿ растёт слишком быстро.
