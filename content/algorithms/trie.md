## Суть за 30 секунд

Trie (префиксное дерево, бор) хранит набор строк так, что **каждый узел — это префикс**, а ребро — очередной символ. Слова с общим началом делят общий путь: «car», «cat» и «cart» используют одни и те же узлы `c → a`. В узле отмечено, заканчивается ли здесь слово.

Аналогия — бумажный словарь с вырубками по краю страниц: открываете раздел «C», в нём подраздел «CA» и так далее. Время поиска зависит только от длины запроса, а не от того, сколько слов в словаре. И главное, чего не умеет хеш-таблица: одним спуском ответить «есть ли слова, начинающиеся с этого префикса» и перечислить их.

## История

- **1959** — Рене де ла Бриандэ описал хранение файловых ключей переменной длины в виде дерева символов.
- **1960** — Эдвард Фредкин опубликовал статью «Trie Memory» и придумал название — от слова re**trie**val. Сам Фредкин произносил его как «три» (tree), но чтобы не путать с деревьями вообще, многие говорят «трай».
- **1968** — Дональд Моррисон предложил **PATRICIA** — сжатое префиксное дерево, где цепочки узлов с одним ребёнком схлопываются в одно ребро. Это предок современных radix tree.
- **1975** — Альфред Ахо и Маргарет Корасик построили на trie алгоритм одновременного поиска множества шаблонов в тексте (Aho–Corasick): к trie добавляются «ссылки неудачи», и текст читается один раз.

## Как работает

Узел содержит ссылки на детей (по одной на символ алфавита) и флаг `isEnd`.

- **Insert(word):** идём от корня по символам; если ребёнка для символа нет — создаём узел. В последнем узле ставим `isEnd = true`.
- **Search(word):** идём по символам; если на каком-то шаге ребёнка нет — слова нет. Дошли до конца — ответ равен `isEnd` последнего узла.
- **StartsWith(prefix):** то же самое, но флаг не важен: дошли до конца префикса — значит, существует хотя бы одно слово с ним.
- **Автодополнение:** спускаемся к узлу префикса и обходим его поддерево DFS-ом, собирая слова.

В визуализации вставляются «car», «cat», «cart», «dog», «do». Обратите внимание: при вставке «cart» новых узлов почти не появляется — путь `c → a → r` уже есть; а «do» вообще не создаёт узлов, только помечает существующий узел `o` как конец слова. Поэтому флаг `isEnd` обязателен: без него нельзя отличить слово «do» от префикса слова «dog».

**Сжатый trie (radix tree, PATRICIA):** если у узла один ребёнок и он не конец слова, цепочку можно схлопнуть в одно ребро с меткой-строкой. Память падает в разы, а для URL-путей, IP-префиксов и ключей с длинными общими началами это стандартный выбор.

## Шаблон на Go

```go
type Trie struct {
	children [26]*Trie // для произвольного алфавита — map[byte]*Trie или map[rune]*Trie
	isEnd    bool
}

func (t *Trie) Insert(word string) {
	node := t
	for i := 0; i < len(word); i++ {
		c := word[i] - 'a'
		if node.children[c] == nil {
			node.children[c] = &Trie{}
		}
		node = node.children[c]
	}
	node.isEnd = true
}

// walk возвращает узел, соответствующий префиксу, или nil.
func (t *Trie) walk(prefix string) *Trie {
	node := t
	for i := 0; i < len(prefix) && node != nil; i++ {
		node = node.children[prefix[i]-'a']
	}
	return node
}

func (t *Trie) Search(word string) bool {
	n := t.walk(word)
	return n != nil && n.isEnd
}

func (t *Trie) StartsWith(prefix string) bool {
	return t.walk(prefix) != nil
}

// Collect возвращает до limit слов с данным префиксом (автодополнение) — DFS по поддереву.
func (t *Trie) Collect(prefix string, limit int) []string {
	var res []string
	buf := []byte(prefix)
	var dfs func(n *Trie)
	dfs = func(n *Trie) {
		if len(res) >= limit {
			return
		}
		if n.isEnd {
			res = append(res, string(buf))
		}
		for c, child := range n.children {
			if child != nil {
				buf = append(buf, byte('a'+c))
				dfs(child)
				buf = buf[:len(buf)-1]
			}
		}
	}
	if n := t.walk(prefix); n != nil {
		dfs(n)
	}
	return res
}
```

Детали Go:

- `word[i]` — это **байт**, а не символ. Для латиницы `a–z` всё корректно, но для кириллицы или эмодзи нужно идти по рунам (`for _, r := range word`) и хранить детей в `map[rune]*Trie`.
- `[26]*Trie` занимает 208 байт на узел на 64-битной платформе, даже если занят один ребёнок. На миллионах слов это заметно — тогда map или сжатый trie.
- Trie есть внутри стандартной библиотеки: `strings.NewReplacer` для общего случая (много шаблонов разной длины) строит префиксное дерево шаблонов и в каждой позиции текста ищет подходящий шаблон спуском по нему, а не перебором всех шаблонов. А маршрутизатор `net/http.ServeMux` в Go 1.22+ хранит шаблоны путей в дереве по сегментам пути.

## Сложность

L — длина слова/префикса, Σ — размер алфавита, N — суммарная длина всех слов.

| Операция | Время | Память |
|---|---|---|
| Insert | O(L) | до L новых узлов |
| Search / StartsWith | O(L) | O(1) |
| Автодополнение | O(L + размер поддерева) | O(глубины) на рекурсию |
| Хранение словаря | — | O(N · Σ) с массивами, O(N) с map или в сжатом виде |

Для сравнения: хеш-таблица тоже ищет слово за O(L) (нужно посчитать хеш), но на запрос «все слова с префиксом» ей придётся перебрать все ключи.

## Когда применять

- В условии есть слова **«prefix», «starts with», «autocomplete», «словарь»**.
- Нужно искать **много слов одновременно** — например, все слова словаря в сетке букв (Word Search II): вместо отдельного DFS для каждого слова идём по сетке и по trie синхронно, отсекая ветки, которых нет в словаре.
- Поиск с шаблоном `.` (любой символ) — DFS по всем детям на позиции `.`.
- «Заменить слова на их кратчайший корень», «самый длинный общий префикс», «посчитать слова с префиксом» (храним счётчик в узле).
- **Максимальный XOR пары чисел** — двоичный trie по битам от старшего к младшему: на каждом бите жадно идём в противоположного ребёнка.

Вариации: счётчики проходов в узлах, удаление слова (снимаем `isEnd`, чистим ставшие пустыми узлы), сжатый trie, Aho–Corasick для поиска множества шаблонов в потоке текста, суффиксные структуры для поиска подстрок.

## Где применяется в реальном мире

### Бигтех
- **Автодополнение (typeahead):** в поисковых строках, IDE и shell — префиксное дерево запросов; в узлах обычно заранее кэшируют top-k популярных продолжений, чтобы не обходить поддерево на каждое нажатие клавиши. Классическая задача системного дизайна.
- **IP-маршрутизация:** поиск самого длинного совпадающего префикса (longest prefix match). В ядре Linux таблица маршрутов IPv4 хранится в LC-trie (`fib_trie`); аппаратные и программные маршрутизаторы используют двоичные и многобитные trie.
- **HTTP-роутеры:** `julienschmidt/httprouter` и Gin (построен на его коде) хранят маршруты в radix tree — поэтому сопоставление пути не зависит от числа маршрутов.
- **Redis:** Streams хранят записи в собственном radix tree (`rax`), где ключ — ID записи; общие префиксы ID (время) схлопываются.

### Финтех
- **Ethereum:** состояние сети (балансы, хранилища контрактов) хранится в Merkle Patricia Trie — сжатом trie, где каждый узел ещё и захеширован. Корень этого дерева записывается в заголовок блока, что позволяет доказать баланс счёта, не скачивая всё состояние.
- **Определение платёжной системы и банка по номеру карты:** первые 6–8 цифр (BIN/IIN) определяют эмитента; поиск самого длинного совпадающего префикса по таблице BIN-диапазонов — естественная задача для trie по цифрам (одна из распространённых реализаций).
- **Поиск инструментов в торговых терминалах:** автодополнение по тикерам и названиям бумаг — префиксный поиск по относительно небольшому словарю, который удобно держать в памяти в виде trie.

### Геймдев
- **Словесные игры:** «самая быстрая программа для Scrabble» Аппеля и Якобсона (1988) хранила словарь в DAWG — сжатом trie, где совпадающие окончания тоже объединены. Боты для Boggle и «Эрудита» перебирают поле синхронно со спуском по trie.
- **Фильтр чата:** поиск запрещённых слов в сообщениях — Aho–Corasick (trie + ссылки неудачи) находит все вхождения всех слов за один проход по тексту.
- **Консоль разработчика и чат-команды:** автодополнение команд и переменных консоли по введённому префиксу.

## Типичные ошибки

- Забыть флаг конца слова: после вставки «dog» поиск «do» должен вернуть `false`, а после вставки «do» — `true`. Без `isEnd` это неразличимо.
- `word[i]-'a'` для заглавных букв, цифр или Unicode → выход за границы массива или неверный индекс.
- Перепутать `Search` и `StartsWith`: первый проверяет `isEnd`, второй — нет.
- Word Search II: не удалять найденные слова из trie (или не снимать `isEnd`) — дубликаты в ответе и лишний перебор; не обрезать опустевшие ветки — TLE.
- При удалении слова удалить узлы, которые являются префиксами других слов (например, удаляя «do», снести путь к «dog»).
- Хранить `[26]*Trie` для миллионов длинных строк и упереться в память, когда хватило бы map или сжатого дерева.
