## Суть за 30 секунд

Union-Find (DSU, disjoint set union) хранит разбиение элементов на группы и умеет две операции: **Find(x)** — «кто представитель группы x» и **Union(x, y)** — «слить группы x и y». Два элемента в одной группе, если у них один представитель.

Каждая группа — дерево, где элемент хранит ссылку на родителя, а корень и есть представитель. Аналогия — компании и поглощения: чтобы узнать, кому принадлежит фирма, идём по цепочке «материнская компания → её материнская → …» до головной. Слияние двух групп — подчинить одну головную компанию другой. С двумя оптимизациями (сжатие путей и объединение по рангу/размеру) обе операции работают за амортизированное O(α(n)), где α — обратная функция Аккермана, не превышающая 4 для любых практических n.

## История

- **1964** — Бернард Галлер и Майкл Фишер описали структуру «леса с указателями на родителя» в статье «An improved equivalence algorithm» (Communications of the ACM) — для обработки объявлений эквивалентности переменных в компиляторах (EQUIVALENCE в Фортране).
- **1975** — Роберт Тарьян доказал, что с объединением по рангу и сжатием путей последовательность из m операций занимает O(m · α(n)), — одна из самых известных амортизированных оценок в алгоритмике.
- **1984** — Тарьян и Ян ван Леувен проанализировали варианты сжатия (в том числе path halving и path splitting, которые проще и не требуют рекурсии).
- **1989** — Майкл Фредман и Майкл Сакс доказали, что эта оценка оптимальна: быстрее в общем случае нельзя.

Самое известное применение — алгоритм Крускала для минимального остовного дерева (1956), который без DSU работал бы заметно медленнее.

## Как работает

Храним массив `parent`: изначально `parent[i] = i` — каждый элемент сам себе корень, т.е. n групп по одному элементу.

- **Find(x):** идём по `parent`, пока не дойдём до корня (`parent[r] == r`).
- **Union(x, y):** находим корни `rx = Find(x)` и `ry = Find(y)`. Если они равны — x и y уже в одной группе (а если мы добавляли ребро графа, это ребро **замыкает цикл**). Иначе подвешиваем один корень к другому: `parent[ry] = rx`.

Без оптимизаций деревья могут вытянуться в цепочки, и Find станет O(n). Две оптимизации это лечат:

1. **Объединение по рангу или размеру:** подвешиваем меньшее (по высоте-рангу или числу элементов) дерево к большему. Высота тогда не превышает log n — уже O(log n) на операцию.
2. **Сжатие путей:** во время Find перевешиваем узлы пути ближе к корню. В полной версии все узлы пути начинают указывать прямо на корень; в варианте **path halving** каждый узел перевешивается на «деда» — это один простой цикл без рекурсии и почти тот же эффект.

В визуализации 8 элементов объединяются парами, затем пары — в четвёрки, и последний `union(3,7)` сливает две четвёрки в одно множество. Деревья подвешиваются по рангу, поэтому остаются низкими. Следите за строкой `parent` на шаге `union(3,7)`: внутри `find(3)` и `find(7)` срабатывает сжатие путей — узел 3 перевешивается со своего родителя 2 прямо на корень 0, а 7 — с 6 на корень 4. Если бы мы после этого вызвали `union` для двух элементов, уже лежащих в одном множестве, он вернул бы `false`: в терминах графа такое ребро замкнуло бы цикл.

**Чего DSU не умеет:** разъединять множества (удалять рёбра) и отвечать на вопрос «какой путь между x и y». Для удаления рёбер есть приём «обработать запросы в обратном порядке» (удаление превращается в добавление) или DSU с откатами (без сжатия путей).

## Шаблон на Go

```go
type DSU struct {
	parent []int
	size   []int
	count  int // число множеств
}

func NewDSU(n int) *DSU {
	d := &DSU{parent: make([]int, n), size: make([]int, n), count: n}
	for i := range d.parent {
		d.parent[i] = i
		d.size[i] = 1
	}
	return d
}

// Find со сжатием пути (path halving): каждый узел перевешиваем на «деда».
func (d *DSU) Find(x int) int {
	for d.parent[x] != x {
		d.parent[x] = d.parent[d.parent[x]]
		x = d.parent[x]
	}
	return x
}

// Union по размеру: меньшее дерево подвешиваем к большему.
// Возвращает false, если x и y уже в одном множестве (ребро замкнуло бы цикл).
func (d *DSU) Union(x, y int) bool {
	rx, ry := d.Find(x), d.Find(y)
	if rx == ry {
		return false
	}
	if d.size[rx] < d.size[ry] {
		rx, ry = ry, rx
	}
	d.parent[ry] = rx
	d.size[rx] += d.size[ry]
	d.count--
	return true
}
```

```go
// Крускал: минимальное остовное дерево. Рёбра {u, v, w} по возрастанию веса;
// берём ребро, только если оно соединяет разные компоненты.
func kruskal(n int, edges [][3]int) (total int) {
	slices.SortFunc(edges, func(a, b [3]int) int { return a[2] - b[2] })
	d := NewDSU(n)
	for _, e := range edges {
		if d.Union(e[0], e[1]) {
			total += e[2]
		}
	}
	return total
}
```

Детали Go:

- В стандартной библиотеке DSU нет — он пишется за пару минут, и это нормально написать с нуля на собеседовании.
- Итеративный `Find` (path halving) не рекурсивен — никаких проблем с глубиной стека и меньше накладных расходов, чем у рекурсивного полного сжатия.
- Элементы — не числа (email, строки, координаты)? Отобразите их в индексы через `map[string]int` или для сетки используйте `r*C + c`. Срезы `[]int` значительно быстрее, чем `map[string]string` для `parent`.
- `size` удобнее `rank`: он заодно отвечает на «размер группы элемента» (`size[Find(x)]`).

## Сложность

| Операция | Время | Память |
|---|---|---|
| Find / Union с рангом и сжатием | O(α(n)) амортизированно — практически O(1) | O(n) на весь DSU |
| Только ранг/размер (без сжатия) | O(log n) | O(n) |
| Без оптимизаций | O(n) в худшем случае | O(n) |
| Подсчёт компонент | O(1) — поддерживаем счётчик | — |
| Крускал | O(E log E) — доминирует сортировка | O(V + E) |

## Когда применять

- **«Сколько групп / компонент»**, когда рёбра приходят по одному: Number of Provinces, Number of Connected Components, острова, которые появляются со временем (Number of Islands II).
- **«Какое ребро лишнее / замыкает цикл»** — Redundant Connection: первое ребро, для которого `Union` вернул `false`.
- **«Является ли граф деревом»** — n−1 ребро и ни одно не замкнуло цикл.
- **Отношения эквивалентности:** Accounts Merge (общий email → один человек), Satisfiability of Equality Equations (`a==b` объединяем, потом проверяем `a!=b`), Similar String Groups.
- **Минимальное остовное дерево** — Крускал; «соединить все точки минимальной ценой» (Min Cost to Connect All Points).
- **Офлайн-запросы с порогом:** отсортировать рёбра и запросы по весу и добавлять рёбра по мере роста порога.

Вариации: DSU с весами на рёбрах к родителю (Evaluate Division — хранится отношение к корню), DSU с откатами, «виртуальные» вершины (например, «граница сетки» в Surrounded Regions), обратная обработка удалений.

## Где применяется в реальном мире

### Бигтех
- **Компиляторы и вывод типов:** унификация в выводе типов в стиле Хиндли–Милнера (семейство ML, OCaml, Haskell) обычно реализуется через union-find над переменными типов: «эти два типа равны» = Union. Исторически DSU и появился для эквивалентностей в компиляторе Фортрана.
- **Компьютерное зрение:** разметка связных компонент на бинарном изображении (например, `connectedComponents` в OpenCV) — двухпроходные алгоритмы, где эквивалентности меток на первом проходе сливаются через union-find.
- **Entity resolution / identity graph:** склейка записей об одном пользователе из разных источников (email, телефон, cookie, устройство) — пары «это один человек» объединяются в DSU; распространённая практика в рекламных и аналитических системах.
- **Кластеризация:** single-linkage кластеризация — это Крускал, остановленный, когда осталось k компонент; используется, например, для группировки похожих документов и логов.

### Финтех
- **Антифрод-кольца:** аккаунты, которые делят устройство, карту, телефон, адрес или IP, объединяются в одну группу; большая группа из «независимых» клиентов — сигнал о мошеннической ферме. Union-find позволяет делать это потоково и почти бесплатно на событие.
- **Кластеризация адресов в Bitcoin:** эвристика «общего владения входами» — все входы одной транзакции считаются принадлежащими одному владельцу; адреса склеиваются в union-find. Подход описан в исследовании Meiklejohn et al. «A Fistful of Bitcoins» (2013) и широко применяется в блокчейн-аналитике.
- **KYC и группы связанных лиц:** юрлица с общими бенефициарами или директорами объединяются в группу для расчёта совокупного лимита и концентрации риска.

### Геймдев
- **Генерация лабиринтов (рандомизированный Крускал):** все стены в случайном порядке; стена ломается, если клетки по обе стороны ещё в разных множествах. Получается идеальный лабиринт без циклов.
- **Игра Hex и похожие на неё «соединялки»:** проверка победы — соединены ли две противоположные стороны доски; стороны заводятся как виртуальные элементы DSU, и каждый ход — несколько Union.
- **Процедурная генерация и разрушаемость:** объединение клеток или вокселей в регионы и проверка связности карты; при добавлении блоков DSU отвечает «образовался ли единый массив» за O(α(n)).

## Типичные ошибки

- Сравнивать `x == y` или `parent[x] == parent[y]` вместо `Find(x) == Find(y)` — у элементов одной группы родители могут быть разными.
- Подвешивать **элементы**, а не **корни**: `parent[x] = y` вместо `parent[Find(x)] = Find(y)` — ломает структуру.
- Забыть оптимизации — на цепочке длиной 10⁵ Find становится O(n), и решение получает TLE.
- Уменьшать счётчик компонент при каждом вызове Union, а не только при успешном слиянии.
- Пытаться удалить ребро — DSU это не поддерживает; нужен обратный порядок обработки.
- При отображении строк в индексы забыть завести индекс для элемента, который встречается только в одной паре.
