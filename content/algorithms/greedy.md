## Суть за 30 секунд

Жадный алгоритм на каждом шаге делает **локально лучший выбор** и больше к нему не возвращается: никакого перебора, никакой таблицы. Обычно это сортировка плюс один проход — O(n log n) или O(n). Сложность не в коде, а в **доказательстве**: жадность часто выглядит правильной и при этом ошибается.

Аналогия: кассир выдаёт сдачу, каждый раз беря самую крупную подходящую монету. Для рублей и евро это оптимально. Для монет {1, 3, 4} и суммы 6 — нет: жадно 4+1+1 (три монеты), а лучше 3+3.

## История

Жадные идеи старше самого термина: алгоритмы Краскала (1956), Прима (1957) и Дейкстры (1959) — жадные. Теоретическую основу дала теория **матроидов**: Хасслер Уитни ввёл понятие в 1935 году, а позже (Радо, 1957; Эдмондс, 1971) было показано, что жадный алгоритм находит оптимум при *любых* весах ровно тогда, когда структура допустимых множеств — матроид. В 1952 году студент MIT Дэвид Хаффман придумал жадный алгоритм построения оптимального префиксного кода.

**Алгоритм Кадане** появился в 1977 году. Ульф Гренандер поставил задачу о подмассиве с максимальной суммой (в двумерном виде — для поиска закономерностей в оцифрованных изображениях). Майкл Шамос нашёл решение «разделяй и властвуй» за O(n log n), а статистик Джей Кадане, услышав задачу на семинаре в Карнеги-Меллоне, почти сразу предложил линейный алгоритм. Историю популяризовал Джон Бентли в колонке «Programming Pearls». Формально Кадане — это DP с памятью O(1), но в задачах он стоит рядом с жадными.

## Как работает

**Когда жадность корректна.** Нужны два свойства:

1. **Жадный выбор безопасен** — существует оптимальное решение, содержащее наш первый шаг.
2. **Оптимальная подструктура** — после этого шага остаётся задача того же вида.

**Аргумент обмена** — стандартный способ доказать пункт 1. Пример: выбрать максимум непересекающихся встреч. Жадность: сортируем по **времени окончания** и берём всё, что не конфликтует. Доказательство: возьмём любое оптимальное расписание; его первая встреча заканчивается не раньше нашей (мы взяли самую рано заканчивающуюся). Заменим её на нашу — конфликтов не появится, количество не изменится. Повторяя обмен, превращаем оптимум в жадное решение — значит, жадное тоже оптимально.

**Матроиды на уровне интуиции.** Если «допустимые наборы» устроены так, что (а) подмножество допустимого набора допустимо и (б) из меньшего допустимого набора всегда можно дорасти, добавив элемент из большего, — жадность «бери самый тяжёлый элемент, если набор остаётся допустимым» оптимальна. Леса в графе — матроид, поэтому Краскал работает. Наборы монет с суммой — не матроид, поэтому Coin Change в общем случае требует DP.

**Алгоритм Кадане.** Идём слева направо и держим `cur` — лучшую сумму подмассива, **заканчивающегося** в текущей позиции. Либо продолжаем предыдущий подмассив (`cur + a[i]`), либо начинаем заново с `a[i]` — если накопленный хвост отрицательный, он только мешает. Глобальный ответ — максимум `cur` за весь проход.

**Jump Game.** Поддерживаем `far` — самую дальнюю клетку, до которой можно добраться. Если текущий индекс оказался дальше `far` — застряли. Мы не выбираем конкретные прыжки — мы жадно расширяем **множество** достижимых клеток, и поэтому ничего не теряем.

## Шаблон на Go

```go
// Кадане: максимальная сумма непустого подмассива и его границы [l, r].
// Работает и когда все числа отрицательные.
func maxSubArray(a []int) (best, l, r int) {
	cur, start := a[0], 0
	best = a[0]
	for i := 1; i < len(a); i++ {
		if cur < 0 { // отрицательный хвост только мешает — начинаем заново
			cur, start = a[i], i
		} else {
			cur += a[i]
		}
		if cur > best {
			best, l, r = cur, start, i
		}
	}
	return best, l, r
}

// Jump Game: можно ли допрыгнуть до конца.
func canJump(a []int) bool {
	far := 0
	for i, x := range a {
		if i > far {
			return false
		}
		far = max(far, i+x)
	}
	return true
}

// Jump Game II: минимум прыжков — BFS по «уровням», сжатый в O(1) памяти.
func jump(a []int) int {
	jumps, curEnd, far := 0, 0, 0
	for i := 0; i < len(a)-1; i++ {
		far = max(far, i+a[i])
		if i == curEnd { // уровень кончился — обязаны прыгнуть
			jumps++
			curEnd = far
		}
	}
	return jumps
}
```

Классика с аргументом обмена — выбор встреч:

```go
// Максимум непересекающихся интервалов [start, end): сортируем по КОНЦУ.
func maxNonOverlapping(iv [][2]int) int {
	iv = slices.Clone(iv)
	slices.SortFunc(iv, func(x, y [2]int) int { return cmp.Compare(x[1], y[1]) })
	count, lastEnd := 0, 0
	for k, x := range iv {
		if k == 0 || x[0] >= lastEnd {
			count++
			lastEnd = x[1]
		}
	}
	return count
}
```

Go-детали: `slices.SortFunc` с `cmp.Compare` (Go 1.21+) безопаснее компаратора через вычитание — оно может переполниться на краях `int`. Не инициализируйте `best` нулём в Кадане: для массива из одних отрицательных чисел ответ отрицательный.

## Сложность

| Алгоритм | Время | Память |
|---|---|---|
| Кадане | O(n) | O(1) |
| Jump Game I / II | O(n) | O(1) |
| Выбор встреч (сортировка по концу) | O(n log n) | O(1) доп. (или O(n) на копию) |
| Код Хаффмана | O(n log n) | O(n) |
| Жадная сдача (каноническая система) | O(число номиналов) | O(1) |

## Когда применять

- Есть очевидный «порядок важности» (по концу, по дедлайну, по плотности ценности), и после выбора задача сводится к меньшей того же вида.
- Ограничения n до 10⁵–10⁶ — DP за O(n²) не пройдёт, а сортировка пройдёт.
- Нужен **максимум/минимум одной величины**, а не перечисление всех вариантов.
- Типовые сигналы: «максимальная сумма подмассива», «можно ли дойти», «минимум прыжков/остановок», «минимум стрел, чтобы лопнуть шары», «распределить конфеты», «заправки по кругу» (Gas Station), «расписание задач с охлаждением».
- Сначала попробуйте найти контрпример на 3–4 элементах. Нашёлся — переходите к DP.

## Где применяется в реальном мире

### Бигтех
- **Коды Хаффмана** в DEFLATE (gzip, zip, PNG) и в JPEG: жадно сливаем два самых редких символа, пока не останется одно дерево, — получаем оптимальный префиксный код.
- **Маршрутизация OSPF/IS-IS**: каждый роутер считает кратчайшие пути жадной Дейкстрой по карте сети (link-state).
- **Балансировка нагрузки и планирование**: эвристики вида «отдай задачу наименее загруженному серверу» или LPT (самые длинные задачи — первыми) дают гарантированные приближения и повсеместно применяются в планировщиках.
- **Рекомендации и подбор выдачи**: для субмодулярных целей (покрытие, разнообразие) жадный выбор гарантирует приближение 1 − 1/e — классический результат, на котором строят задачи вида «максимизация влияния» в соцсетях.

### Финтех
- **Best Time to Buy and Sell Stock** — Кадане на разностях соседних цен; той же «однопроходной» логикой (бегущий максимум + текущая просадка) считают **максимальную просадку** портфеля.
- **Выдача наличных в банкоматах**: для канонических номиналов жадная сдача оптимальна, но при ограниченном числе купюр в кассетах жадность может завести в тупик — тогда нужен перебор или DP.
- **Исполнение ордера в биржевом стакане**: рыночная заявка «съедает» уровни от лучшей цены к худшей по приоритету цена–время — это правило матчинга, и оно жадное по построению.

### Геймдев
- **Greedy meshing** в воксельных движках: соседние одинаковые грани жадно сливаются в максимальные прямоугольники, что резко сокращает число треугольников.
- **Упаковка спрайтов в атлас**: эвристики Shelf, Skyline, MaxRects жадно ставят следующий (обычно самый большой) спрайт в лучшее свободное место.
- **Утилитарный ИИ (utility AI)**: агент каждый тик выбирает действие с максимальной оценкой полезности — простое и предсказуемое жадное поведение.

## Типичные ошибки

- Не доказать и не проверить жадность на маленьких контрпримерах — классика: Coin Change жадно.
- Сортировать встречи по **началу** или по **длине** вместо конца.
- В Кадане начинать с `best = 0` — неверно для массивов из отрицательных чисел.
- В Кадане сбрасывать `cur` при `cur + a[i] < 0` и при этом терять ответ для «все отрицательные».
- В Jump Game II делать лишний прыжок, перебирая цикл до `len(a)`, а не `len(a)−1`.
- Путать «жадно» и «DP»: если выбор зависит от будущего (как в 0/1-рюкзаке), жадность не годится.
