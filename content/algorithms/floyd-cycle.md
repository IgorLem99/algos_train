## Суть за 30 секунд

Пускаем по цепочке два указателя: «черепаха» делает 1 шаг, «заяц» — 2. Если цепочка кончается, заяц первым упрётся в `nil` — цикла нет. Если есть цикл, заяц войдёт в него и начнёт догонять черепаху, сокращая отрыв на 1 за ход, — они обязательно встретятся.

Вторая фаза находит **вход в цикл**: черепаху возвращаем в начало, и оба идут по 1 шагу — встретятся ровно на входе. Всё это без `map` посещённых узлов: O(n) времени и O(1) памяти.

Интуиция — бегуны на стадионе: если трасса замкнута, быстрый обязательно догонит медленного на круг; если трасса прямая, они не встретятся никогда.

## История

- Алгоритм традиционно приписывают **Роберту Флойду**: Дональд Кнут во втором томе TAOCP (1969) упоминает метод в упражнениях к разделу о случайных числах со ссылкой на Флойда. При этом опубликованной статьи Флойда с этим алгоритмом не существует, так что точная атрибуция остаётся неопределённой.
- **1975** — Джон Поллард опубликовал ρ-метод факторизации: последовательность `x → x² + c (mod n)` рано или поздно зацикливается, и цикл ищется именно черепахой и зайцем. Буква ρ (ро) — форма «хвост + петля».
- **1980** — Ричард Брент предложил более быстрый вариант поиска цикла (степени двойки) и применил его для ускорения метода Полларда.
- Название «черепаха и заяц» — отсылка к басне Эзопа.

## Как работает

Пусть до цикла `μ` шагов (длина «хвоста»), а длина цикла — `λ`.

**Фаза 1 — есть ли цикл.** `slow` и `fast` стартуют в голове; `slow = slow.Next`, `fast = fast.Next.Next`. Если `fast` или `fast.Next` стал `nil` — цикла нет. Иначе они встретятся внутри цикла: когда оба в цикле, расстояние между ними уменьшается на 1 за ход, поэтому «перепрыгнуть» друг через друга невозможно.

**Фаза 2 — где вход.** Пусть встреча случилась через `k` шагов. Заяц прошёл `2k`, черепаха `k`, и заяц обогнал её на целое число кругов: `2k − k = k` делится на `λ`. Ставим черепаху в голову, зайца оставляем в точке встречи и двигаем обоих по 1 шагу. Через `μ` шагов черепаха стоит на входе. Заяц к этому моменту в сумме прошёл `k + μ` шагов от головы, а так как `k` кратно `λ`, это та же позиция, что и `μ` шагов, — тоже вход. Встреча — ровно на входе в цикл.

**Длина цикла** (если нужна): от точки встречи идём одним указателем, пока не вернёмся, — `λ` шагов.

В визуализации список 1 → 2 → … → 7 → 3: хвост `μ = 2`, цикл `λ = 5`. Указатели встречаются в узле 6 (через `k = 5` шагов), а во второй фазе — в узле 3, это и есть вход.

## Шаблон на Go

```go
type ListNode struct {
	Val  int
	Next *ListNode
}

// hasCycle — фаза 1.
func hasCycle(head *ListNode) bool {
	slow, fast := head, head
	for fast != nil && fast.Next != nil {
		slow, fast = slow.Next, fast.Next.Next
		if slow == fast {
			return true
		}
	}
	return false
}

// detectCycle — вход в цикл или nil.
func detectCycle(head *ListNode) *ListNode {
	slow, fast := head, head
	for fast != nil && fast.Next != nil {
		slow, fast = slow.Next, fast.Next.Next
		if slow == fast { // фаза 2
			p := head
			for p != slow {
				p, slow = p.Next, slow.Next
			}
			return p
		}
	}
	return nil
}
```

Алгоритм работает для любой функции `f` на конечном множестве: последовательность `x0, f(x0), f(f(x0)), …` обязана зациклиться. Поэтому шаблон легко обобщить:

```go
// floyd возвращает длину хвоста mu и длину цикла lam
// для последовательности x0, f(x0), f(f(x0)), ...
func floyd[T comparable](f func(T) T, x0 T) (mu, lam int) {
	tort, hare := f(x0), f(f(x0))
	for tort != hare {
		tort, hare = f(tort), f(f(hare))
	}
	tort = x0
	for tort != hare {
		tort, hare = f(tort), f(hare)
		mu++
	}
	lam, hare = 1, f(tort)
	for tort != hare {
		hare = f(hare)
		lam++
	}
	return mu, lam
}

// findDuplicate (LeetCode 287): n+1 чисел из [1..n]. Массив — функция
// i → nums[i]; два индекса ведут в одно значение, и это значение — вход в цикл.
func findDuplicate(nums []int) int {
	slow, fast := nums[0], nums[nums[0]]
	for slow != fast {
		slow, fast = nums[slow], nums[nums[fast]]
	}
	slow = 0
	for slow != fast {
		slow, fast = nums[slow], nums[fast]
	}
	return slow
}

// isHappy (LeetCode 202): последовательность «сумма квадратов цифр»
// либо приходит в 1, либо зацикливается.
func isHappy(n int) bool {
	next := func(x int) int {
		s := 0
		for ; x > 0; x /= 10 {
			d := x % 10
			s += d * d
		}
		return s
	}
	slow, fast := n, next(n)
	for fast != 1 && slow != fast {
		slow, fast = next(slow), next(next(fast))
	}
	return fast == 1
}
```

Заметки по Go: сравнение `slow == fast` для указателей — сравнение адресов, именно это и нужно (значения узлов могут повторяться). Сборщик мусора Go корректно собирает циклические структуры, так что цикл в списке не приводит к утечке — он приводит к бесконечному обходу. Альтернатива с памятью O(n) — `map[*ListNode]bool` посещённых узлов; так, например, `encoding/json` после большой глубины вложенности начинает запоминать уже виденные указатели, чтобы вернуть ошибку вместо бесконечной рекурсии на циклических данных.

## Сложность

| операция | время | память |
| --- | --- | --- |
| есть ли цикл | O(μ + λ) = O(n) | O(1) |
| вход в цикл | O(n) | O(1) |
| длина цикла | O(λ) дополнительно | O(1) |
| вариант с map посещённых | O(n) | O(n) |
| алгоритм Брента | O(n), обычно меньше вызовов f | O(1) |

## Когда применять

- «Есть ли в списке цикл?», «где он начинается?» — классика.
- Последовательность задана функцией `x → f(x)` на конечном множестве: Happy Number, повторяющиеся состояния, генераторы псевдослучайных чисел.
- **Массив значений-индексов** (`nums[i]` в диапазоне индексов) и запрещено менять массив и тратить память — Find the Duplicate Number.
- Нужна память O(1) там, где решение через `map` посещённых очевидно — это сигнал, что ждут Флойда.
- Родственные приёмы того же семейства «быстрый/медленный»: середина списка, палиндромность списка, пересечение двух списков.

## Где применяется в реальном мире

### Бигтех
- **GNU coreutils `factor`**: раскладывает большие числа на множители ρ-методом Полларда, внутри которого — поиск цикла в последовательности `x → x² + c (mod n)`.
- **Криптоанализ**: поиск коллизий хеш-функций и дискретного логарифма ρ-методом; параллельный вариант ван Оршота — Винера с «выделенными точками» применялся в распределённых вычислениях, решавших публичные ECC-задачи Certicom.
- **Тестирование PRNG и хеш-итераций**: длину периода последовательности состояний находят поиском цикла, не храня все пройденные состояния.

### Финтех
- **Стойкость ECDSA**: подписи транзакций (secp256k1 в Bitcoin и Ethereum, P-256 в платёжной инфраструктуре) держатся на том, что лучшая известная универсальная атака на дискретный логарифм — ρ-метод Полларда — требует порядка √n шагов. Поэтому 256-битная кривая даёт около 128 бит безопасности.
- **Валидация цепочек ссылок**: «транзакция заменена транзакцией X», `parent_id` счетов, цепочки переадресации платежей — при обходе такой цепочки проверка на петлю за O(1) памяти защищает от зависания на испорченных данных. Общая практика для данных, связанных указателями.
- **Монте-Карло в риск-моделях**: при использовании собственных генераторов с небольшим состоянием проверка длины периода гарантирует, что сценарии не начнут повторяться.

### Геймдев
- **Процедурная генерация**: на простых генераторах (LCG, xorshift с малым состоянием) поиск цикла показывает период — после него мир, лут или узор начнут повторяться.
- **Детерминированные симуляции**: обнаружение повторяющихся состояний (осцилляторы в клеточных автоматах вроде Game of Life, ИИ, застрявший в цикле состояний) — состояния хешируются и проверяются черепахой и зайцем без хранения истории.
- **Валидаторы в редакторах уровней**: цепочки «следующая точка маршрута», телепорты, ссылки триггеров — проверка, что цепочка заканчивается (или, для патрульного маршрута, действительно замкнута), с поиском точки, где начинается петля.

## Типичные ошибки

- **Проверка `slow == fast` до первого шага**: в начале они равны (оба в голове), и алгоритм сразу «находит» цикл. Сначала шаг, потом сравнение.
- **Разыменование nil**: условие цикла должно быть `fast != nil && fast.Next != nil` — иначе `fast.Next.Next` паникует на списке нечётной длины.
- **Фаза 2 с разной скоростью**: во второй фазе оба указателя идут по 1 шагу; если заяц продолжит прыгать по 2, встреча будет не на входе.
- **Сравнение значений вместо узлов**: `slow.Val == fast.Val` ломается на повторяющихся значениях.
- **Find the Duplicate: неправильный старт** — обе фазы должны начинаться из одной и той же «головы» (индекс 0), иначе равенство `k ≡ 0 (mod λ)` не даёт входа.
- **Применение к бесконечному множеству состояний**: если f не обязана зацикливаться (например, растущий счётчик), алгоритм не завершится — нужен лимит шагов.
