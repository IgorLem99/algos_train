## Суть за 30 секунд

Почти все задачи на интервалы решаются одним приёмом: **отсортировать** (по началу, по концу или все концы вместе как события) и пройти **один раз** слева направо, поддерживая маленькое состояние — текущий слитый интервал, счётчик активных отрезков или кучу концов. После сортировки пересекающиеся интервалы оказываются рядом, и проверка «всех пар» за O(n²) больше не нужна.

Аналогия: вертикальная линия едет по календарю слева направо. В каждый момент она «видит» только те встречи, которые сейчас идут. Отслеживая, когда встречи начинаются и заканчиваются, легко ответить, сколько переговорок нужно в пике.

## История

Интервальное планирование — классика исследования операций и учебников по алгоритмам; жадное решение «сортируй по концу» складывалось как фольклор, и единственного автора у него нет. Метод **заметающей прямой** (sweep line) оформился в вычислительной геометрии в 1970-х: Шамос и Хоуи (1976) применили его для проверки, пересекаются ли отрезки, а Бентли и Оттманн (1979) — для перечисления всех пересечений. Сегодня это базовый инструмент — от растеризации полигонов до физических движков.

## Как работает

**Два интервала `[a, b]` и `[c, d]` пересекаются ⇔ `a ≤ d` и `c ≤ b`.** Запомните эту формулу: она проще, чем перебор четырёх случаев расположения. Для полуоткрытых `[a, b)` неравенства строгие.

**Слияние (Merge Intervals):**

1. Сортируем по началу.
2. Идём по списку: если текущий начинается не позже конца последнего в результате — продлеваем конец до `max(конец, текущий конец)`; иначе начинаем новый интервал.

`max` обязателен: `[1, 10]` поглощает `[2, 3]`, и конец не должен «уменьшиться» до 3.

**Sweep line по событиям.** Каждый интервал превращаем в два события: `(start, +1)` и `(end, −1)`. Сортируем по времени и идём со счётчиком: его максимум — пиковое число одновременно активных интервалов (минимум переговорок, максимум одновременных соединений). При равном времени порядок событий определяет семантику: если сначала обработать `−1`, то `[1, 5)` и `[5, 8)` не конфликтуют.

**Другие частые схемы:**

- **Вставка интервала** в отсортированный непересекающийся список — три фазы: всё, что целиком левее; всё, что пересекается (сливаем); всё, что правее. O(n).
- **Минимум удалений, чтобы не было пересечений** = n − (максимум непересекающихся), а максимум — жадно по концу.
- **Пересечение двух отсортированных списков интервалов** — два указателя: пересечение `[max(a,c), min(b,d)]`, двигаем тот, кто раньше заканчивается.
- **Онлайн-запросы** «что пересекается с [l, r]» — дерево интервалов или отсортированная структура (в Go — например, B-tree из сторонних библиотек).

## Шаблон на Go

```go
type Interval struct{ Start, End int } // замкнутый [Start, End]

// Пересекаются ли два замкнутых интервала. Для полуоткрытых [s, e) — строгие <.
func overlaps(a, b Interval) bool { return a.Start <= b.End && b.Start <= a.End }

// merge сливает все пересекающиеся интервалы.
func merge(iv []Interval) []Interval {
	iv = slices.Clone(iv) // не портим вход вызывающего
	slices.SortFunc(iv, func(a, b Interval) int { return cmp.Compare(a.Start, b.Start) })
	var res []Interval
	for _, x := range iv {
		if n := len(res); n > 0 && x.Start <= res[n-1].End {
			res[n-1].End = max(res[n-1].End, x.End) // max! [1,10] поглощает [2,3]
		} else {
			res = append(res, x)
		}
	}
	return res
}
```

```go
// minMeetingRooms — максимум одновременно идущих встреч [start, end).
func minMeetingRooms(meetings [][2]int) int {
	type event struct{ t, delta int }
	ev := make([]event, 0, 2*len(meetings))
	for _, m := range meetings {
		ev = append(ev, event{m[0], +1}, event{m[1], -1})
	}
	slices.SortFunc(ev, func(a, b event) int {
		if a.t != b.t {
			return a.t - b.t
		}
		return a.delta - b.delta // при равном времени сначала −1
	})
	cur, best := 0, 0
	for _, e := range ev {
		cur += e.delta
		best = max(best, cur)
	}
	return best
}
```

Go-детали: `res[n-1].End = ...` работает, потому что элемент слайса адресуем; а вот `for _, x := range res { x.End = ... }` изменит лишь копию. Для времени используйте `time.Time` с методами `Before/After` или Unix-метки — сравнивать `time.Time` через `==` не стоит (в структуре есть локация и показания монотонных часов — используйте `Equal`). Альтернатива событиям — два отсортированных массива начал и концов и два указателя.

## Сложность

| Операция | Время | Память |
|---|---|---|
| Слияние интервалов | O(n log n) | O(n) |
| Вставка в отсортированный список | O(n) | O(n) |
| Пик нагрузки (sweep по событиям) | O(n log n) | O(n) |
| Пересечение двух отсортированных списков | O(n + m) | O(n + m) |
| Запрос к дереву интервалов | O(log n + k) | O(n) |
| Наивная проверка всех пар | O(n²) | O(1) |

## Когда применять

- В условии есть **отрезки времени, диапазоны, бронирования, встречи**, `[start, end]`.
- Вопросы: «слить пересекающиеся», «сколько ресурсов нужно одновременно», «есть ли конфликт», «найти свободные окна», «минимум удалений/стрел».
- Ответ зависит только от **порядка концов**, а не от точных значений, — признак sweep line.
- Вариации: Meeting Rooms I/II, Insert Interval, Non-overlapping Intervals, Minimum Number of Arrows, Interval List Intersections, Employee Free Time, My Calendar I/II/III, «линия горизонта» (The Skyline Problem — sweep + куча).

## Где применяется в реальном мире

### Бигтех
- **Календари и поиск свободного времени**: занятые интервалы всех участников сливаются, а «дыры» между ними — кандидаты для встречи. Это ровно Merge Intervals + Employee Free Time.
- **Бронирования в PostgreSQL**: range-типы (`tstzrange`) и оператор пересечения `&&` вместе с exclusion constraint (`EXCLUDE USING gist`) гарантируют на уровне БД, что брони одной комнаты не пересекаются.
- **Аллокаторы памяти**: при освобождении блока соседние свободные диапазоны сливаются (coalescing), иначе память фрагментируется.
- **Сетевые стеки**: TCP-получатель хранит множество полученных диапазонов байт и сообщает их отправителю через SACK; новые сегменты сливаются с уже полученными.

### Финтех
- **Восстановление пропусков в рыночных данных**: принятые диапазоны sequence numbers сливаются, а дыры между ними запрашиваются повторно (в FIX это Resend Request с `BeginSeqNo`/`EndSeqNo`).
- **Velocity-проверки в антифроде**: «не более N операций за скользящее окно» — sweep по событиям со счётчиком.
- **Торговые сессии и календари**: пересечение интервалов работы бирж в разных часовых поясах для кросс-рыночных стратегий, проверка, что тарифы и периоды действия ставок не перекрываются.

### Геймдев
- **Sweep and prune** — классическая broad-phase проверка столкновений: концы AABB сортируются по оси, и пары-кандидаты получаются только у перекрывающихся отрезков (такой вариант есть, например, в Bullet Physics).
- **Растеризация полигонов**: scanline-алгоритм идёт по строкам экрана, держа «таблицу активных рёбер», и закрашивает интервалы между пересечениями.
- **Баффы, кулдауны и аудио**: длительности эффектов — интервалы, наложение баффов — их слияние, а лимит одновременно звучащих звуков — пиковая нагрузка, как в Meeting Rooms.

## Типичные ошибки

- Забыть `max` при слиянии и «укоротить» интервал, поглощающий следующий.
- Не определиться с **закрытыми и полуоткрытыми** интервалами: `[1,5]` и `[5,8]` пересекаются, а `[1,5)` и `[5,8)` — нет.
- В sweep line неправильно упорядочить события с одинаковым временем.
- Сортировать по началу там, где нужна сортировка по концу (максимум непересекающихся, стрелы).
- Сравнивать через вычитание `a.t - b.t` при очень больших значениях (переполнение) — используйте `cmp.Compare`.
- Модифицировать копию в `range`-цикле вместо элемента слайса.
