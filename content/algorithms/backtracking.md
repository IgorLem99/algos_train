## Суть за 30 секунд

Backtracking — это аккуратный полный перебор. Решение строится по шагам: на каждом шаге делаем **выбор**, рекурсивно **достраиваем** остальное, а затем **отменяем** выбор и пробуем следующий вариант. По сути это DFS по неявному дереву решений, где узел — частичное решение, а лист — полное.

Аналогия — прохождение лабиринта с клубком нити: дошли до тупика — сматываем нить до последней развилки и идём в другой коридор. Сила метода — в **отсечениях** (pruning): если частичное решение уже не может привести к ответу, мы не заходим в целое поддерево вариантов. Это превращает «теоретически 2ⁿ» в «на практике быстро» для судоку, N ферзей и подобных задач.

## История

Термин «backtrack» ввёл американский математик Деррик Генри Лемер в 1950-х годах. Одно из первых описаний метода как общего алгоритма дал Р. Дж. Уокер в 1960 году, а в 1965 году Соломон Голомб и Леонард Баумерт опубликовали обзор «Backtrack Programming», где сформулировали технику в общем виде и обсудили оценку размера дерева перебора.

Сами задачи гораздо старше: головоломку о восьми ферзях опубликовал шахматист Макс Беццель в 1848 году, ей интересовался Гаусс. В 2000 году Дональд Кнут описал «Dancing Links» — элегантную реализацию перебора с возвратом для задачи точного покрытия (Algorithm X), где отмена выбора делается за O(1) перешиванием указателей двусвязного списка.

## Как работает

Любая задача на backtracking описывается тремя вещами:

- **Состояние** — частичное решение: текущий путь `path`, массив `used`, помеченные клетки сетки.
- **Выборы** — какие варианты можно добавить к состоянию на этом шаге.
- **Условия** — когда решение готово (база рекурсии) и когда ветку можно отсечь.

Псевдокод каркаса:

```text
dfs(состояние):
    если решение готово: сохранить копию, return
    если ветка безнадёжна: return            // отсечение
    для каждого допустимого выбора:
        применить выбор
        dfs(новое состояние)
        отменить выбор                       // backtrack
```

В визуализации — дерево решений для подмножеств `[1,2,3]`: на уровне d решаем судьбу элемента d+1 — взять (влево) или не брать (вправо). Листьев 2³ = 8 — это все подмножества. Обратите внимание, как после каждого листа подсветка пути «откатывается» к ближайшей развилке: это и есть возврат.

Три классические формы дерева решений:

- **Подмножества / сочетания** — передаём `start`, чтобы брать элементы только правее последнего выбранного: так `{1,2}` и `{2,1}` не считаются дважды.
- **Перестановки** — порядок важен, поэтому на каждом уровне перебираем все элементы, а уже использованные пропускаем по массиву `used`.
- **Расстановки с ограничениями** (N ферзей, судоку, раскраска) — на каждом шаге ставим значение в очередную клетку и сразу проверяем, не нарушены ли правила. Для N ферзей проверка O(1) через множества занятых столбцов и диагоналей (`r+c` и `r−c`).

Как отсекать: сортировка входа и `break`, когда кандидат уже больше остатка суммы; проверка ограничений **до** рекурсии, а не в листе; пропуск дубликатов (`if i > start && nums[i] == nums[i-1] { continue }` после сортировки); оценка «даже если взять всё оставшееся, не хватит».

## Шаблон на Go

```go
// Подмножества: выбрать → углубиться → отменить.
func subsets(nums []int) [][]int {
	var res [][]int
	var path []int
	var dfs func(start int)
	dfs = func(start int) {
		res = append(res, slices.Clone(path)) // копия! path дальше изменится
		for i := start; i < len(nums); i++ {
			path = append(path, nums[i]) // выбрать
			dfs(i + 1)                   // углубиться
			path = path[:len(path)-1]    // отменить (backtrack)
		}
	}
	dfs(0)
	return res
}

// Комбинации с суммой target (числа можно брать повторно) и отсечением.
func combinationSum(nums []int, target int) [][]int {
	slices.Sort(nums)
	var res [][]int
	var path []int
	var dfs func(start, remain int)
	dfs = func(start, remain int) {
		if remain == 0 {
			res = append(res, slices.Clone(path))
			return
		}
		for i := start; i < len(nums); i++ {
			if nums[i] > remain {
				break // pruning: дальше числа только больше
			}
			path = append(path, nums[i])
			dfs(i, remain-nums[i]) // i, а не i+1: число можно взять ещё раз
			path = path[:len(path)-1]
		}
	}
	dfs(0, target)
	return res
}
```

```go
// Перестановки: состояние — путь и массив used.
func permute(nums []int) [][]int {
	var res [][]int
	path := make([]int, 0, len(nums))
	used := make([]bool, len(nums))
	var dfs func()
	dfs = func() {
		if len(path) == len(nums) {
			res = append(res, slices.Clone(path))
			return
		}
		for i, x := range nums {
			if used[i] {
				continue
			}
			used[i] = true
			path = append(path, x)
			dfs()
			path = path[:len(path)-1]
			used[i] = false
		}
	}
	dfs()
	return res
}
```

Детали Go:

- **Главная ловушка — алиасинг срезов.** `res = append(res, path)` сохраняет заголовок среза, который указывает на тот же массив, что и `path`. Следующие `append`/обрезки перезапишут уже «сохранённый» ответ. Всегда копируйте: `slices.Clone(path)` (Go 1.21+) или `append([]int(nil), path...)`.
- Рекурсивное замыкание объявляется в два шага: `var dfs func(...)`, затем `dfs = func(...) {...}` — иначе замыкание не видит само себя.
- Пакет `regexp` в Go построен на подходе RE2 и **не использует backtracking**: время сопоставления линейно от длины входа. Цена — нет обратных ссылок (`\1`) и lookaround. Это сознательный выбор ради защиты от ReDoS (см. ниже).

## Сложность

| Задача | Время | Память (без учёта ответа) |
|---|---|---|
| Подмножества | O(n · 2ⁿ) | O(n) — глубина рекурсии и path |
| Перестановки | O(n · n!) | O(n) |
| Сочетания из n по k | O(k · C(n, k)) | O(k) |
| N ферзей | не больше O(n!), с отсечениями намного меньше | O(n) |
| Общий случай | O(b^d): b — ветвление, d — глубина | O(d) |

Множитель n (или k) — это копирование каждого найденного решения в ответ.

## Когда применять

- Просят **все** варианты: «все подмножества», «все перестановки», «все комбинации с суммой», «все разбиения строки на палиндромы», «все корректные скобочные последовательности».
- Расстановки с ограничениями: N ферзей, судоку, раскраска графа, Word Search (найти слово в сетке).
- **Маленькие ограничения** — n ≤ 15–20 почти всегда намекает на экспоненциальный перебор.
- Если просят не все варианты, а **количество** или **оптимум** и подзадачи повторяются — скорее всего, это DP; backtracking + мемоизация и есть DP «сверху вниз».

Вариации: элементы с дубликатами (сортировка + пропуск равных соседей), повторное использование элемента (`dfs(i)` вместо `dfs(i+1)`), перебор по битовой маске вместо рекурсии (для подмножеств при n ≤ 20), branch and bound — отсечение по оценке лучшего возможного ответа.

## Где применяется в реальном мире

### Бигтех
- **Движки регулярных выражений:** PCRE, Perl, Java, Python, JavaScript используют сопоставление с возвратом, что даёт обратные ссылки, но и экспоненциальное время на «злых» шаблонах (ReDoS). Известные инциденты: сбой Stack Overflow в июле 2016 года и глобальный сбой Cloudflare 2 июля 2019 года — оба из-за катастрофического backtracking в регулярном выражении. RE2 и Go `regexp` гарантируют линейное время.
- **Разрешение зависимостей:** резолвер pip (с версии 20.3) и резолвер Cargo перебирают версии пакетов с возвратом при конфликте. Для контраста: Go modules сознательно используют Minimal Version Selection, которому перебор не нужен.
- **SAT-решатели:** алгоритмы DPLL и CDCL — это поиск с возвратом плюс распространение ограничений и обучение на конфликтах. На них работают верификация железа и софта, а также пакетные менеджеры вроде libsolv (zypper, dnf) и conda.

### Финтех
- **Сверка платежей (reconciliation):** найти набор входящих платежей, сумма которых совпадает со строкой банковской выписки, — задача subset sum. На небольших кандидатных наборах её решают перебором с возвратом и отсечениями по сумме и датам (распространённая практика в инструментах автоматической сверки).
- **Аудит смарт-контрактов:** инструменты символьного исполнения (Mythril, Manticore) перебирают пути выполнения контракта, откатывая состояние на развилках, и проверяют достижимость уязвимых состояний SMT-решателем (например, Z3).
- **Оптимизация с целочисленными ограничениями:** MIP-решатели (Gurobi, CPLEX и др.) используют branch and bound — перебор с возвратом и отсечением по оценке. Так решают построение портфеля с лотностью и лимитами, распределение ликвидности.

### Геймдев
- **Генерация лабиринтов:** алгоритм «recursive backtracker» — случайный DFS: прорубаем проход к случайному непосещённому соседу, а в тупике возвращаемся назад. Даёт лабиринты с длинными извилистыми коридорами.
- **Генераторы головоломок:** судоку, «Какуро», нонограммы — решатель с возвратом проверяет, что у сгенерированной головоломки ровно одно решение.
- **Процедурная генерация по ограничениям:** Wave Function Collapse (Максим Гумин, 2016) расставляет тайлы с учётом правил соседства; при противоречии одни реализации перезапускают генерацию, другие — откатываются назад, т.е. делают backtracking.

## Типичные ошибки

- Сохранять `path` без копирования — все ответы в `res` окажутся одинаковыми или «битыми».
- Забыть отменить выбор: не снять `used[i]`, не вернуть букву в клетку сетки после пометки `'#'` в Word Search.
- Путать `dfs(i)`, `dfs(i+1)` и `dfs(0)`: повторное использование элемента, сочетания без повторов и перестановки соответственно.
- Пропуск дубликатов через `i > 0` вместо `i > start` — теряются корректные ответы вроде `[1,1,2]`.
- Проверять ограничения только в листе — дерево не отсекается, и решение получает TLE.
- Возвращать результат из глубины рекурсии через возвращаемое значение там, где проще накопить ответ в замыкании (и наоборот — забыть прервать перебор, когда нужен лишь один ответ, как в судоку).
