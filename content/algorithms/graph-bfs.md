## Суть за 30 секунд

BFS обходит граф **волнами**: сначала стартовая вершина, затем все её соседи (расстояние 1), затем их непосещённые соседи (расстояние 2) и так далее. Порядок задаёт обычная очередь FIFO. Отсюда главное свойство: **первый раз, когда BFS добрался до вершины, он добрался по кратчайшему пути** (в числе рёбер).

Аналогия — круги на воде от брошенного камня или слух, который за день узнают все друзья, за два дня — друзья друзей. Если в задаче нужно «минимальное число шагов», а все шаги стоят одинаково, — это BFS.

## История

BFS открывали независимо несколько раз. Конрад Цузе описал его в 1945 году для поиска компонент связности графа (работа была опубликована значительно позже). Эдвард Мур в 1959 году опубликовал его как способ найти кратчайший путь в лабиринте, а Ч. Й. Ли в 1961 году — как алгоритм трассировки соединений на печатных платах (его до сих пор называют «волновым алгоритмом Ли»).

В 1970 году Ч. Дж. Чейни предложил копирующий сборщик мусора, в котором сама область, куда копируются объекты, служит очередью BFS, — красивый пример того, как алгоритм обхода стал частью среды выполнения языков.

## Как работает

1. Кладём старт в очередь и **сразу помечаем** его посещённым, `dist[start] = 0`.
2. Пока очередь не пуста: достаём вершину `u` из головы.
3. Для каждого соседа `v`, который ещё не посещён: помечаем, `dist[v] = dist[u] + 1`, запоминаем `parent[v] = u` и кладём `v` в хвост.
4. Путь восстанавливается от цели назад по `parent`.

Почему кратчайший путь гарантирован: в любой момент в очереди лежат вершины не более чем **двух соседних уровней** — d и d+1, причём все вершины уровня d стоят впереди. Значит, вершины обрабатываются строго в порядке неубывания расстояния, и вершина уровня d+1 не может быть открыта раньше, чем через вершину уровня d.

В визуализации BFS идёт по сетке со стенами от левого верхнего угла к правому нижнему. Числа в клетках — расстояние от старта: видно, как волна обтекает стены. Когда цель достигнута, путь восстанавливается по ссылкам на родителя.

<div data-viz="grid-bfs"></div>

**Сетка как граф.** Клетка — вершина, соседи — 4 (или 8) смежные клетки. Отдельно строить список смежности не нужно: соседей перебираем массивом направлений и проверяем границы, стены и посещённость.

**Мультиисточниковый BFS.** Если волна идёт от нескольких источников одновременно (гниющие апельсины, расстояние до ближайших ворот, «через сколько минут огонь дойдёт»), все источники кладутся в очередь **сразу**, с расстоянием 0. Это эквивалентно фиктивной супервершине, соединённой со всеми источниками.

**BFS по состояниям.** Вершиной графа может быть не клетка, а состояние: `(клетка, набор собранных ключей)`, `(слово)` в Word Ladder, комбинация замка в Open the Lock. Рёбра — допустимые переходы. Главное — правильно определить, что считается «посещённым».

**Двунаправленный BFS.** Запускаем волны с обоих концов и останавливаемся, когда они встретились. При ветвлении b и расстоянии d вместо ~b^d вершин посещаем ~2·b^(d/2) — огромная экономия для Word Ladder и социальных графов.

**0-1 BFS.** Если веса рёбер только 0 и 1, используем дек: рёбра веса 0 кладём в начало, веса 1 — в конец. Получаем Дейкстру за O(V+E).

## Шаблон на Go

```go
// Кратчайшее расстояние (в рёбрах) от src до всех вершин; -1 — недостижима.
func bfs(adj [][]int, src int) []int {
	dist := make([]int, len(adj))
	for i := range dist {
		dist[i] = -1
	}
	dist[src] = 0 // помечаем при ДОБАВЛЕНИИ в очередь, а не при извлечении
	queue := []int{src}
	for len(queue) > 0 {
		u := queue[0]
		queue = queue[1:]
		for _, v := range adj[u] {
			if dist[v] == -1 {
				dist[v] = dist[u] + 1
				queue = append(queue, v)
			}
		}
	}
	return dist
}
```

```go
// Мультиисточниковый BFS по сетке ('#' — стена). Все источники стартуют одновременно.
func gridBFS(grid [][]byte, sources [][2]int) [][]int {
	R, C := len(grid), len(grid[0])
	dist := make([][]int, R)
	for i := range dist {
		dist[i] = make([]int, C)
		for j := range dist[i] {
			dist[i][j] = -1
		}
	}
	queue := make([][2]int, 0, len(sources))
	for _, s := range sources {
		dist[s[0]][s[1]] = 0
		queue = append(queue, s)
	}
	dirs := [4][2]int{{1, 0}, {-1, 0}, {0, 1}, {0, -1}}
	for len(queue) > 0 {
		cur := queue[0]
		queue = queue[1:]
		for _, d := range dirs {
			r, c := cur[0]+d[0], cur[1]+d[1]
			if r < 0 || c < 0 || r >= R || c >= C || grid[r][c] == '#' || dist[r][c] != -1 {
				continue
			}
			dist[r][c] = dist[cur[0]][cur[1]] + 1
			queue = append(queue, [2]int{r, c})
		}
	}
	return dist
}
```

Детали Go:

- Очередь на срезе (`queue[0]`, `queue = queue[1:]`, `append`) — идиоматичный и быстрый вариант. `container/list` медленнее из-за аллокации на каждый элемент и приведения типов.
- `queue[1:]` не освобождает память в начале массива, но при росте `append` переаллоцирует срез и старое начало уйдёт сборщику мусора. Если очередь живёт долго (сервис, а не задача), лучше кольцевой буфер или обработка уровнями с двумя срезами `cur`/`next`, которые переиспользуются.
- Для `dist`/`visited` на плотных индексах берите срезы, а не `map`: это в разы быстрее. `map[string]bool` оправдан для состояний-строк (Word Ladder).
- Массив направлений как `[4][2]int` (массив, а не срез) живёт на стеке и не аллоцируется.

## Сложность

| Вариант | Время | Память |
|---|---|---|
| BFS по списку смежности | O(V + E) | O(V) — очередь и dist |
| BFS по сетке R×C | O(R·C) | O(R·C) |
| Двунаправленный BFS | ~O(b^(d/2)) | ~O(b^(d/2)) |
| 0-1 BFS (дек) | O(V + E) | O(V) |
| BFS по матрице смежности | O(V²) | O(V) |

## Когда применять

- **«Минимальное число шагов / ходов / преобразований»**, когда каждый шаг стоит одинаково: Word Ladder, Open the Lock, ход коня, кратчайший путь в лабиринте.
- **«Кратчайший путь в невзвешенном графе / сетке»**, «расстояние до ближайшего X».
- **Одновременное распространение от нескольких источников:** Rotting Oranges, Walls and Gates, 01 Matrix, «огонь и беглец».
- **«Все вершины на расстоянии k»**, «уровни», «степени связи».
- Если веса разные — это уже Дейкстра; если веса 0/1 — 0-1 BFS; если нужен не кратчайший путь, а просто связность — подойдёт и DFS.

Вариации: восстановление пути через `parent`, BFS с ограничением глубины, BFS по уровням (как в деревьях, с фиксацией `len(queue)`), BFS по расширенному состоянию (позиция + маска ключей / оставшиеся «пробития стен»), алгоритм Кана для топологической сортировки — тоже BFS.

## Где применяется в реальном мире

### Бигтех
- **Социальные графы:** отметки «контакт 2-го/3-го уровня» в профессиональных сетях — это расстояние в рёбрах, т.е. BFS, ограниченный глубиной (часто двунаправленный, чтобы не раскрывать миллионы вершин).
- **Веб-краулеры:** очередь URL-ов (frontier) обходится приблизительно в порядке BFS; классическая работа Найорка и Винера (2001) показала, что обход в ширину рано находит качественные страницы.
- **Сборщики мусора:** алгоритм Чейни — BFS по графу живых объектов, где очередью служит сама целевая полу-область памяти. Такая схема применяется в копирующих сборщиках молодого поколения.
- **Сети:** рассылка link-state объявлений в OSPF и IS-IS — лавинная рассылка (flooding) по соседям, которая распространяется по сети волнами, как BFS; в P2P-сетях вроде Gnutella запросы рассылались так же с ограничением TTL.

### Финтех
- **AML и санкционный скрининг:** «какие счета находятся в пределах k переводов от подсанкционного или скомпрометированного» — k-hop обход графа транзакций; графовые СУБД продвигаются для финтеха именно под такие запросы.
- **Блокчейн-аналитика:** отслеживание средств после взлома — обход графа транзакций слоями от адреса-источника, с пометкой расстояния (числа «прыжков») для каждого затронутого адреса. Это общая практика аналитических компаний.
- **Корреспондентские цепочки:** минимальное число банков-посредников между банком отправителя и банком получателя — кратчайший путь в невзвешенном графе корреспондентских отношений (если важны комиссии и сроки, задача становится взвешенной — уже Дейкстра).

### Геймдев
- **Flood fill и карты расстояний:** заливка «ведром», вычисление достижимых клеток; «Dijkstra maps» в рогаликах при равных весах — это BFS от игрока, по которому все монстры одновременно идут «вниз по склону».
- **Flow fields для толп в RTS:** одна волна от цели считает расстояние для всех клеток, затем каждый юнит просто идёт по градиенту. Подход описан, например, в материалах о Supreme Commander 2 (сборник Game AI Pro).
- **Дальность хода в тактических играх:** клетки, достижимые за N шагов (подсветка в духе XCOM), — BFS с ограничением глубины; с разной стоимостью местности — Дейкстра.

## Типичные ошибки

- Помечать вершину посещённой при **извлечении**, а не при добавлении: одна вершина попадает в очередь много раз, на сетке это взрыв памяти и TLE.
- Использовать DFS для кратчайшего пути в невзвешенном графе — DFS находит **какой-то** путь, не кратчайший.
- Применять BFS к взвешенному графу — первым будет найден путь с наименьшим **числом рёбер**, а не с наименьшей стоимостью.
- Ошибка на единицу при подсчёте уровней (считать минуты в Rotting Oranges после последней волны, хотя новых клеток не появилось).
- Не обработать случаи «старт = цель», «цель недостижима» (вернуть -1), «нет ни одного источника».
- Неправильное определение состояния в BFS по состояниям: посещённой считается клетка, хотя должна быть пара (клетка, ключи) — и путь через ту же клетку с новым ключом отсекается.
